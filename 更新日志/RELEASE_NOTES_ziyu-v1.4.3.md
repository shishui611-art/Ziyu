# 字域 v1.4.3 — 本地 Debug 字符映射修复候选

用户报告挂载成功但应用显示方框，且旧版可正常显示。本次没有对应进程的设备证据，不能把具体管理器隔离认定为已证实根因。

## 实际修改

普通 ColorOS 物理字体切换此前主要复制用户字体并恢复原厂行度量。挂载与哈希验证可通过，但原厂路径下的 cmap、字形编号及字库覆盖已经变成用户字体，原厂拥有而用户字体缺少的字符也可能随之丢失。

本版在同一个字体切换事务中，为静态轮廓来源和可信原厂 TrueType 单字体目标补充原厂字体壳编译：保留原厂 cmap/UVS、字形索引、名称、布局和变化轴契约，移植可安全替换的中文、英文与数字轮廓。未覆盖、专用、UVS 及保留复合字形依赖的字形继续使用原厂字形；超出原厂度量契约的字形也保留原厂。部分字符因此可能保持原厂外观。

输出重新解析并核对原厂契约；源文件和快照身份、输出哈希、原有挂载校验和回滚继续执行。编译器与快照内容参与缓存失效，单批相同来源和原厂字体可复用。原有集合编译默认行为保留。

## 适用范围与限制

- 不更改挂载模式，不修改 APatch、Magisk、KernelSU 或元模块的隔离设置，不增加 Zygisk 依赖。
- 变量/彩色来源、TTC/OTC、非 TrueType 原厂轮廓或缺少可信原厂快照时继续既有路径，在度量报告中记录未覆盖原因，不伪称原厂契约已保留。
- 该修改解决上述覆盖和字符映射保留缺口，不保证应用无法访问字体文件、失效路径、进程旧缓存等问题也已解决。
- 安装升级后需重新应用所选字体并完整重启，旧的已提交负载不会仅因更新模块就自动重编译。
