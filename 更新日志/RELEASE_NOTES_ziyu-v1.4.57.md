# 字域 v1.4.57（本地 Debug 试用）

本次减少字体兼容生成中的重复计算，并扩大适合使用原生桥的处理范围。包含 v1.4.56 的 q/y/g/j 下伸字母、连写与轮廓边界修复。

## 改动

- 原生桥生成的 TrueType 字形直接作为已编码字节写入输出。此前 Python 会再展开全部坐标、重复求边界并编码；现在只检查必要的头部、端点、指令、标志与坐标流长度。确实需要一单位原点修正时才展开处理。
- 保留原厂可变字体的竖排度量时，直接提取两个独立虚拟点；不再深复制整份变化数据或插值无关轮廓。遗漏的虚拟点变化按原 IUP 规则为零；点数、VVAR 侧距与竖排原点条件保持校验。
- CFF 字形只为检查实际边界而解码后，恢复已经生成的原生字节码；多面字体复用同来源、轮廓类型及缩放下的边界结果。缓存与现有模板共用 64 MiB 上限。
- HyperOS 对普通 Unicode 字体进行路由裁剪时优先使用已有 HarfBuzz 原生接口。带变体选择符、旧编码或符号映射的字体，继续使用可保留完整显式字形闭包的兼容路径。SVG、原生不支持的格式及原生契约不通过的输入保留既有处理。
- 未更改挂载方式、通知、Root 检测或回滚事务。源变化检查、原厂映射/排版/度量契约与输出验证继续执行。

## 桌面定向核对

使用同一份 51,815 字形的静态字体、本机保存的两个 ColorOS 原厂字体面，在独立 Python 进程和空生成缓存中顺序运行。原生计算使用现有同源 Windows 主机可执行文件；计时包含原生准备、兼容生成、写入和输出契约核对。以下为无 profiler 的第二轮对照，第一轮也约为 52 秒降到 25 秒。

| 字体面 | 修改前 | 修改后 | 耗时减少 |
| --- | --- | --- | --- |
| Hans | 35.168 s | 17.027 s | 51.6% |
| Hant | 17.404 s | 8.131 s | 53.3% |
| 合计 | 52.572 s | 25.158 s | 52.1% |

TrueType 全部字形坐标、轮廓标志、字形顺序，以及除 glyf 编码和相应 head 校验值以外的表字节保持一致；两面的序列化输出契约均通过。使用用户提供的筑紫A圆E字体另生成原厂 CFF2 字体面，对照结果所有表字节一致（约 6.9 秒，此样本未报告 CFF 阶段提速）。HyperOS 原生裁剪核对了精确字符集合、保留字形编号和源文件未变化。

## 原生覆盖与限制

可变字体实例化、适合的子集裁剪、静态 TrueType 轮廓准备、TrueType/CFF 到 CFF 的转换已有原生路径。本次处理的是后续重复解码、度量保留及 HyperOS 裁剪漏用原生的问题。

CFF/CFF2 到二次 TrueType 曲线的近似转换、带额外仿射变换的少量拉丁/数字组合、复杂映射的字形闭包以及排版契约核对，仍由现有 FontTools 处理。现有原生接口尚不能等价覆盖这些操作，保留兼容路径。任务编排、JSON 和挂载事务也继续使用原有实现。

以上是电脑的兼容生成阶段数据，不能换算为手机完整应用提速。未运行完整测试套件，未安装 APK、刷模块、重启或发布。手机应用、软重启后显示与实际耗时仍待验收。制品为现有 Debug 证书签名的本地试用版。
