# ziyu v1.4.25 — 直接曲线转换替代近似样条合并（本地 Debug 候选）

本版落实性能分析发现的耗时点：原厂 CFF/CFF2 集合逐面替换字形时，旧流程使用 `Qu2CuPen` 反复搜索「用较少三次曲线近似合并多段二次曲线」，这部分占明显编译耗时。现改为数学等价的**精确二次→三次度提升**，不再合并/近似曲线；来源为 glyf 时仍执行轮廓方向反转。

## 改动

- `common/composite_collection_build.py`：
  - 新增 `_ExactCubicT2Pen`：在既有 Type 2 整数舍入前逐段提升二次曲线，保留隐含点处理；
  - CFF/CFF2 目标转换改用该 pen，删除 `Qu2CuPen` 合并搜索；
  - 全离线全角轮廓（on-curve-less）仍按原有逻辑逐字保留原厂并记录，不扩大支持范围；
  - Type 2 指令压缩、跨面模板复用、逐面/合集合契约、来源变化检查、输出哈希、逐面证明与统一提交/回滚全部保留。

## 桌面同条件实测

条件：同一真实设备组合来源（15.5 MB 自定义组合字体）与设备 32 MB 原厂集合快照，完整五个字体面构建 + 独立契约验证，Windows 单进程（无 fork 并行），fontTools 4.63.0。

| 版本 | 构建耗时 | 输出大小 | 独立验证 |
|---|---|---|---|
| v1.4.24（近似合并） | 96.97 s | 121,371,908 B | PASS |
| v1.4.25（精确提升） | 89.81 s | 125,375,604 B | PASS |

- 构建耗时 **-7.4%**；输出体积 **+3.3%**（仍低于 128 MB 单文件限制，余量约 8.8 MB）。曲线由近似合并改为精确表示后编码字节不同，因此输出 SHA-256 不同。
- 桌面单进程数据不代表手机：手机为有界多进程路径，实际耗时与 128 MB 体积余量未实测。

## 字形核对（对照旧/新输出，face 0）

| 项目 | 结果 |
|---|---|
| 被替换且字节不同的字形 | 16,275 |
| 字宽不一致 | 0 |
| 轮廓方向（面积符号）不一致 | 0 |
| 边界最大差异 | 0.58 font unit（upem 1000，≈0.06% em） |
| 面积最大相对差异 | 0.44% |
| 未修改原厂字形字节 | 完全一致 |
| 原厂 PROTECTED 排版契约 | 完全一致（PASS） |

锚点数量不同是预期结果：近似合并把多段二次曲线合并为较少三次曲线，精确提升则每段生成一个三次曲线；边界与面积差异在合并误差（`max_err` 0.5）与整数舍入范围内。

## 试过但未采用的优化

- 「录制轮廓与测量边界合并为一次绘制」（TeePen）：在真实五面构建中反而慢约 14%（每操作双 pen 转发开销），已回退。
- 关闭 Type 2 指令压缩（`optimize=False`）：单面快约 2.8 s（-8.8%），但输出 +5.3%，完整集合会逼近 128 MB 上限，可靠性不足，未采用。

## 未验证范围

- 未在手机安装、刷入、重启，未做显示对照；手机实际应用耗时、输出体积余量与渲染效果仍待实测。
- 桌面 Windows 无 `os.fork`，并行路径以单进程运行；本版速度数据不是手机并行的速度。
