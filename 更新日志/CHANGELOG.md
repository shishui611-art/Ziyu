# 字域更新日志

## v1.4.55（2026-10-29）

- 减少 ColorOS 在多个系统字体位置重复处理相同字体的时间；OnePlus 15 同条件下，该兼容阶段从 110.099 秒降至 55.907 秒。此数据只代表兼容阶段。
- 修复 fi 连写仍显示旧字体，以及静态/可变字体混合处理时部分字符替换结果不稳定的问题。
- 修复合法的大型多面中文字体集合被误判超限的问题，并改善大型字体集合的生成速度。
- 调整软重启期间的字体加载判断，优化页面返回的手势预览与取消效果。
- 保留 Emoji、图标、等宽字体以及字体来源、生成结果和失败回滚检查。完整应用和其他设备组合仍待验收。
## v1.4.54（2026-10-29，本地 Debug）

- 修复原厂多面 CJK 集合生成时误用 128 MiB 单文件输入限制，导致合法 TTC 在合并后被拒绝的问题。单面输出仍限制为 128 MiB，多面输出按面数及本次请求剩余的 384 MiB 总预算约束。
- 合并时直接向临时文件写入并保留 FontTools 表共享，逐次限制文件大小，超额不发布；保留逐面契约、源变化检查及原字体回滚。
- 包含 v1.4.53 的原生 CFF 转换；编译、包完整性和本地验证范围详见同版本说明，用户设备应用尚待验收。


## v1.4.53（本地 Debug 试用）

- CFF/CFF2 目标增加原生批处理：TrueType 供体在 C++ 中分解轮廓、精确升阶二次曲线并反转方向，生成无提示和子程序依赖的 Type 2 程序；CFF/CFF2 静态供体使用现有固定 HarfBuzz 读取轮廓。

- 包含 v1.4.52 的软重启清理判定与两层跟手返回修正。桌面验证与耗时对照见本次版本说明；不以桌面数字宣称手机提速。本次仅本地交付，未上传或发布。

- 包含 v1.4.38 的部分原生字体处理路径：静态 TrueType 字形准备、可变字体实例化、Google 字体裁剪，以及 CFF2 导出冻结默认轴；不适用的输入继续走原有 FontTools 路径，CFF/CFF2 曲线转换和原厂契约流程并未整体原生化。验证数据和范围见 v1.4.50 版本说明。

## v1.4.32（本地 Debug 候选）

- 修正集合逐面替换把「默认 UVS 条目」指向的字形也整批保留原厂的问题。Noto CJK 集合里约 1.35 万个汉字字形被默认 UVS 引用，原先全部保留原厂可变字形，与替换后的组合字体字形字重不一致，造成同一段中文粗细混排。现在只保留非默认 UVS 目标（format-14 直接命名的专用变体字形），默认 UVS 解析到普通编码字形时允许替换；字形 ID 与 format-14 表字节不变，原厂布局契约与输出校验保留。
- 设备导出字体实测（同一组合来源 + 原厂集合，完整五面 + 独立契约验证）：首面替换中文字 17,166 → 30,652，保留共享槽 13,539 → 402（常用汉字仅 3 个，其余为兼容汉字、标点与组合符号）；其余面替换数同步提高；契约验证 PASS，输出体积由 125.4 MB 降到 123.1 MB。
- 同步更新回归断言：默认 UVS 目标现在跟随替换，共享槽位与未覆盖字形仍保留原厂。
- 本版仅本地构建打包，不安装、不刷入、不上传；手机显示与字重一致性待验收。

# ziyu v1.4.16 — 组合字体原厂集合共享字形修复（本地 Debug 候选）

用户手机 v1.4.10 日志中的组合字体切换在兼容路径失败：中文/英文取幼圆、数字取数字新的组合，在逐面生成原厂 NotoSansCJK 集合时报告「原厂共享字形 U+00A0 对应不同来源轮廓，不能安全覆盖」，整个集合生成与本次切换中止。

- 原因：本机原厂 NotoSansCJK 集合把 U+0020 与 U+00A0（以及 U+002D/U+00AD/U+2011、U+00B7/U+2022/U+2027/U+30FB、U+2003/U+3000、部分部首与统一汉字等别名组）映射到同一个原厂字形，只保留一个宽度；而组合来源为这些字符提供不同字形或宽度。一个原厂槽位无法同时容纳两个不同的来源字形，原实现把这种无法满足的映射当成致命错误。
- 修正：集合逐面编译遇到这类共享字形冲突时保留该原厂槽位，并把被保留的槽位与字符记录到逐面证明（`retainedSharedConflictSlots`、`retainedSharedConflicts`），不再中止整个集合；其余可安全替换的中文、拉丁和数字字形继续替换。原厂 cmap/UVS、字形索引、布局与垂直度量契约、逐面证明、输出哈希、源变化检查和回滚条件全部保留。
- 日志中另一条「文本目标包含无效动作：/system/fonts/NotoSansHanifiRohingya-Regular.otf」是 v1.4.10 通用计划校验问题，v1.4.11 已修正，本版包含该修正。
