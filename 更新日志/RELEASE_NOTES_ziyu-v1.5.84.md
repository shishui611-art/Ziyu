# 字域 v1.5.84

## 软重启与模块升级

PLK110 的只读启动记录显示，v1.5.83 在 2026-11-16 13:59 的 Android 重启过程中，FontManagerService_create 设置系统字体映射时出现空 Typeface 异常，启动动画随后持续等待系统就绪。用户确认先执行内核软重启，随后完整重启。下一次启动时，NoMount v2.3.0 (720) 检测到上次未清除的启动标记并触发保护。

源码复核确认一处交接缺口。KernelSU 更新模块目录后，旧目录中的软重启清理记录可能丢失，同一内核中的旧 NoMount 重定向仍然存在。默认字体及缺少旧发布记录的状态还可能跳过 NoMount 清理。本次为模块更新记录安装时的内核启动标识，重载时结合当前启动标识与上次后端记录恢复清理入口。清理在 Android 服务已停止、PID 1 挂载命名空间及管理器重载窗口内执行，完成后才进入字体激活和发布。

清理同时核对当前选中的 NoMount 提供者。默认文字或旧发布记录缺失时，也读取并清理来源属于字域的旧规则，逐条回读，再让管理器重新发布。复用既有来源限制、锁、输出核验和失败回滚，记录规则数量与字域规则的目标、来源路径。完整重启依靠不同启动标识跳过这条恢复路径，性能尚待同条件实测。

安装日志还记录了新模块 Python 在迁移及扫描阶段出现 Permission denied。安装入口已提前准备运行时执行权限，覆盖这些首次调用。

App 和模块诊断补齐升级启动记录、软重启交接状态、软重启日志与模块迁移日志。

## 交付与验证

本轮按项目规范构建正式签名 Debug APK 与内置相同 APK 的模块 ZIP，核对版本、包名、签名、摘要、ZIP 完整性与运行文件清单。交付包排除手机生成的更新启动记录。功能回归、安装、刷入、重启及手机验收待完成。

此次故障当时的完整重定向快照已经缺失，导致空 Typeface 的具体字体和规则仍待确认。以上源码缺陷已修正，其与本次卡机的实际对应及修正效果仍需手机验证。尚需验证升级后软重启、默认字体清理、文字和 Emoji 切换、回滚及随后完整重启的结果。

字体实例化继续使用原生桥优先、失败回退，本次未调整字形或连续字重数据。固定字库基准为酷安 53620096 r1，本轮未执行手机字库覆盖验收。轻量启动继续关闭自动 OTA/开机保护暂停与发布时全量校验。
