# 字域 v1.4.6 — 本地 Debug 主页全局调节与挂载界面候选

## 主页调节

选择非组合字体时，在当前字体下显示“全局字体与显示”卡片。字体大小修改 Android 当前用户的系统字体缩放（50%–200%）；DPI 读取默认显示屏的实际覆盖密度和物理默认值，范围结合本机默认值与当前值确定。支持滑条、精细加减、恢复默认数值后点击应用。拖动不反复调用 Root，不修改字体文件或重新生成字库。

粗细调整使用 Android 12+ 的系统字重偏移。仅当字体轴元数据确认 wght 范围可变化，或静态字体包含多个字重时显示；没有确认能力的系统默认字体、单字重和不支持该系统功能的 Android 版本隐藏粗细，其他两项仍保留。字体轴读取失败可重读，不将失败缓存为“不支持”。组合字体隐藏整张卡片，继续使用字体组合页面的已有控件。

三种主题通过已有 Material、Miuix、COUI 原生卡片、滑条与按钮实现，浅色和深色使用当前主题配色。系统设置按当前前台用户读取，字体能力绑定字体 ID 与来源修订；修改前复核旧值，变化则要求重读，修改后回读。执行失败会尝试恢复旧字体缩放、字重与 DPI，并核对恢复结果；无法确认时明确显示。修改 DPI 会改变整套界面布局和文字大小，Android 可能重建页面；不自动重启。

系统字体缩放与字重调整适用于遵循 Android 配置的界面。应用自行固定字号、内置字体或自行绘制文字时，不保证跟随；本功能不强制修改这些应用。系统字重偏移不同于组合页面的字体轴实例化。没有本版手机回读和实际视觉验收，不能仅以设置项写入成功宣称所有应用已生效。

## 挂载与保护

首页新增带图标的主题挂载按钮，选择界面默认只突出“自动挂载 · 推荐”；OverlayFS、Magic Mount 和字域自挂载在高级选项中以有边框、背景与选中标记的按钮显示。保存与重启行为保留。自动提供者选择、自挂载回退、未知 Root 的 bind、PID 1 核对、来源与输出验证及回滚不变。

用户日志显示系统基准保护挡住执行，旧提示将开机循环保护与基准核验混在一起。现在按保护退出码给出对应处理路径；默认恢复保持 default 目标，不被外部组合标签覆盖。任务中心改为使用真实任务字体，避免仅因报错包含“恢复”就把 SFUI 等自定义字体应用标成“恢复系统字体失败”。这部分修正分类与默认目标约束；保护误判及旧标记迁移的处理见下一节，不把错误文案中的 OTA 当成用户做过系统更新的证据。需在设置 → 开机保护核对状态；safe mode 可由用户解除，OTA 需要可信原厂扫描。

## 无系统更新时的保护误触发与识别回归

用户两份 v1.4.2 日志分别来自 Redmi / Android 16 和 realme / Android 17。Redmi 已成功恢复默认字体后，SFUI 的应用被基准保护挡住；realme 的 NoMount 选择器、LKM 与 API 正常，但字域先在保护处返回，未进行管理器识别即记录 unknown/none，随后被 NoMount 按字域的停用标记跳过。这些记录不证明用户做过 OTA。

旧判断将缺少基准记录填成 `__unknown_prior_fingerprint__`，或只凭旧模板/单个指纹字符串变化生成保护；模块跨版升级也会触发。现改为首次建立独立构建版本、设备与 SDK 基准；仅有展示指纹变化不新建系统变化保护。安装阶段初始化基准，迁移仅由旧推断产生、且没有已准备恢复代次的字域自有停用标记，避免新 hook 根本没有运行机会。真实已记录构建变化的保护、已有恢复代次、开机循环保护、用户 disable/remove/外部排除仍保留。首次迁移没有旧构建观察值，不能追溯证明历史是否发生系统更新；继续执行字体来源、负载、路由和回滚检查。

修正已结束观察任务导致独立扫描不再恢复，以及旧成功退出码冒充可信扫描完成的状态闭环。普通查询不补扫，不在字体应用时强行补扫或全局关闭保护。成功完成真实系统变化后的字体核验时，同步提交独立构建基准，避免每次启动重复判变。

管理器检测增加带超时的当前 su 版本身份查询，沿用环境与本次启动证据；确认的元模块选择器不再因管理器名称暂不明确被直接否定。补充 NoMount 的安装态发现，并在保护拦截时保留只读识别结果。元模块缺少选择器时仍区分“已安装”和“可用于本次挂载”，不把检测成功当作挂载验收。无选择器时每次检测只遍历一次模块目录，再按候选类型复核元数据及 disable/remove，避免为每一种引擎重复遍历全部模块；不跨启动或跨检测缓存。

## 同一个 App 与签名

Debug、正式版统一包名 `io.github.shishui611_art.ziyu`，本地构建不再自动添加 `.debug`。已配置的 GitHub Debug 工作流继续使用正式固定证书并校验指纹，可以覆盖同证书且版本兼容的正式 App。版本号仍按 module.prop 递增，不用重新编号来强行降级。

本机没有正式签名配置，本次本地产物使用已有 Android Debug 证书，不能覆盖不同证书的 GitHub 正式版；也不能保证之后正式包能覆盖用本地 Debug 证书首次安装的 App。要在二者间直接覆盖，需要通过已有正式签名流程构建。没有创建或替换正式密钥，没有自动卸载旧 `.debug` App 或删除私有数据，不绕过 Android 签名校验。
