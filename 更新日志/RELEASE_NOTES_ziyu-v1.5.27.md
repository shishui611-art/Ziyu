# 字域 v1.5.27

本版修三个实际现象。

## 1. 主页还是 323、槽位分类没更新

v1.5.26 改了槽位分类，但设备上的 `config/device-slots.list` 是旧缓存，发现脚本只看 fonts.xml 时间，没有因为“分类规则/模块版本变了”而重建，所以一直沿用旧口径（323，把所有装饰字体和各语种 Noto 都算进去）。

修复：缓存头部写入 `classifier=2` 和 `module_version=<versionCode>`，发现脚本发现两者与当前不符就自动重建。升级后设备实测：

- 设备槽位表：323 → **113 个文本家族**（中文 46 / 数字 5 / 英文 62 / 其它语言 210 不计入）
- 这台 ROM 上真实存在的文本槽位：**约 30 个**（Roboto/SysFont/SourceSans/NotoSerif 等核心字体）
- 如果想覆盖 100+，需要打开下面第 3 条的“其它语言槽位”

## 2. 首页显示“已准备，待本次启动验证”

后端状态已经是 `mounted + verified`，但状态脚本只改了挂载/验证字段，`fontEffectState` 还是 `unverified`，App 因此按“未验证”显示。

修复：后端 `mounted + verified` 且当前字体不是 default 时，状态直接给 `effectiveActive=当前字体`、`fontEffectState=verified`。首页槽位卡也改为显示 **中文 / 数字 / 英文** 三项。

## 3. 想覆盖 100+ 个槽位

这台 ColorOS 17 系统里，除中文/英文/数字文本家族外，其余 200 多个是各语种 Noto（阿拉伯、泰、孟加拉……）和装饰字体。默认不替换它们是安全的，但数量少。

设置 → 存储 新增“其它语言槽位”开关：

- 关闭（默认）：只覆盖中文/英文/数字文本家族（约 30 个真实存在的槽位）；
- 打开：把各语种字体槽位也纳入覆盖，数量可到 **200+**，但阿拉伯、泰文等会回退/显示异常，请自行评估。

打开或关闭后需要**重新应用一次字体并完整重启**，发布阶段才会按新计划重新生成发布树（NoMount 激活的文件数也会随之变化）。

## 说明：NoMount 当前激活 159 个文件

这是上一轮旧计划（152 槽位）产生的发布树。升级 v1.5.27 后：

- 保持“其它语言”关闭：重新发布后发布树会缩到约 45 个文件（文本槽位 + 基础文件）；
- 打开“其它语言”：重新发布后约 220+ 个文件。
