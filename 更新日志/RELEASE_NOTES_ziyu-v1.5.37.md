# 字域 v1.5.37

## 修复：无法创建下一启动字体负载

现象：恢复默认或清理发布树后，应用字体报

```
当前启动字体负载不可读取，请重新刷入当前字域版本
无法创建下一启动字体负载
```

原因：v1.5.34 的恢复清理把 `.ziyu-payload` 整个删掉了，而 legacy 切换要先从当前负载克隆
出下一启动负载；没有可克隆来源就直接失败。

修复：

- `restore_stock_factory.sh`：不再整删 `.ziyu-payload`，而是重置为空骨架
  （`.ziyu-payload/system/fonts`），清掉旧分区与旁路元数据；
- `legacy_v14_4/font_switch_safe.sh`：`stage_clone_live` 在无可克隆负载时用空骨架继续，
  不再把用户卡死在“无法创建下一启动字体负载”。

设备侧已重建空负载骨架，可直接重新应用字体（应用 147MB 可变字体前仍建议先换 PingFang 验证开机）。

## 限制

未做手机验收；空负载后首次应用、重启生效需实机验证。
