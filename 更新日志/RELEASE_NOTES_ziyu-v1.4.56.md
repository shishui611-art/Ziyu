# 字域 v1.4.56（本地 Debug 试用）

这次更新修复了使用部分字体时，小写 q、y、g、j 等下伸字符以及部分连写仍显示系统原字体的问题。

## 更新内容

- 有些字体的 UPEM 较小，字符轮廓缩放到原厂字体槽后会超出原厂 `head` 表记录的全局边界。此前兼容逻辑为保留原厂边界而跳过这些单独字形，造成一段拉丁文字中混有原厂字形。
- 单字体槽和中文字体集合现在会按实际字形扩展全局轮廓边界以及横排、竖排的极值统计，不会为了适应旧统计范围而缩小或裁切用户字形。原厂行距、基线、竖排原点、字形编号、字符映射和布局规则继续校验。
- 修复低 UPEM TrueType 字体合成 ff、ft、ffi 等连写时侧距计算不一致的问题，避免连写又混入原厂字体。
- 源字体确实缺少字符、同一字形编号承担多个冲突字符、数值超出文件格式范围，以及无法正确重建的特殊轮廓，仍会保留原厂字形或中止事务。Emoji、图标、等宽字体等现有保留功能不变。

## 验证说明

使用用户提供的“筑紫A圆E.ttf”和本机留存的 ColorOS 字体面进行定向复现。修改前，5 个下伸字母和 16 个连写被保留；修改后，这 21 个字形全部进入替换结果。该英文字体槽的全局边界从 yMin -271 扩展至 -309。

桌面另核对了静态 TrueType、CFF2、加宽及加深下伸轮廓、最终 TTC 与原厂绑定的逐面证明。序列化后的原厂行距、字符映射、字形编号、布局和竖排原点契约通过；旧格式契约的核对仍兼容。没有运行完整测试套件或据此宣称手机性能提升。

本次没有在用户手机上安装或刷入模块，也没有验证重启后的 Gboard 显示。当前制品是本地 Debug 试用包，不是正式签名版本或 GitHub 发布版。
