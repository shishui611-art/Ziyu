# 字域 v1.4.32（本地 Debug 候选）

修复组合字体在 ColorOS CJK 集合上「同一段中文一部分粗、一部分轻」的主因。

## 根因

集合逐面替换时，`replace_face()` 把「format-14 变体选择表（UVS）指向的字形」也加入必须保留原厂的集合，注释理由是「UVS 表字节不变，则其指向字形也不能改」。但 UVS 里绝大多数是**默认条目**（`glyph_name` 为空），它们通过 base cmap 解析到普通编码字形——Noto CJK 集合里约 1.35 万个汉字字形被默认 UVS 引用，于是这些汉字全部保留原厂轮廓。

原厂集合是可变字体（wght 400–900），保留下来的汉字仍是可变字形（默认 400，系统请求粗体时变粗）；而替换进去的字形来自固定字重的组合字体。两者字重不同步，就出现同一段中文粗细混排。v1.4.30 修的是兼容槽位的 1 单位取整误判，这一条是集合路径上的另一个、更大的来源。

## 修复

- 只把**非默认 UVS 目标**（format-14 直接命名的专用变体字形）加入保留集合；
- 默认 UVS 条目解析到 base cmap 的普通编码字形时允许替换：字形 ID 不变、format-14 表字节不变，因此 UVS 映射关系与布局契约都不受影响，只是该字形外观随整字体替换；
- 原厂布局契约、来源变化检查、输出校验、逐面证明与回滚条件全部保留。

| 面 1 | 30,372 → **30,669** | 473 → **319** |

- 首面剩余 402 个保留字形中，CJK 统一汉字只有 **3 个**，其余是兼容汉字（102）、兼容补充（40）、标点/全角（5）、扩展 A（1）等，正常中文排版几乎不会遇到；
- 另有 2 个组合符号（U+302A/U+302B，零宽）因原厂 `hhea` 度量边界保留，与字重无关；
- 独立契约验证 **PASS**；输出体积 125.4 MB → **123.1 MB**；
