# 字域 v1.5.21

本版解决 v1.5.20 启用字域时 zygote PID 仍然超过 5000 的剩余原因。

## 实测定位

v1.5.20 开机日志显示：

- 字域自己的 `post-fs-data` 已降到 **325 个 PID、约 0.14 秒**（16:54:29.497 开始，29.637 结束）。
- 但 ksud `post-fs-data` 总时长仍有 **6.52 秒**，zygote 在 10.66 秒启动、PID **5821**。
- 慢的是中间的 metamodule 挂载阶段：16:54:29.640 → 16:54:35.137 整整 **5.5 秒**，全部花在 NoMount 元模块上。
- NoMount 的脚本接管逻辑会 `find` 模块根下所有 `*.sh`，再对每个脚本做 `stat`、内容检查、`sh -n` 等操作。字域模块里有 **170 个** shell 脚本（`common/` 158 个），是全部模块（258 个）中的大多数；禁用字域时这个阶段约 1 秒，启用后多出约 5 秒。

## 本版修改

- 安装时（`customize.sh`）把 `common/` 移到 `data/common/`，并创建 `common -> data/common` 相对符号链接。
- 开机时（`post-fs-data.sh`）做同样的兜底迁移，处理直接替换文件、未走安装脚本的更新。
- NoMount 会裁剪模块根下的 `data/` 目录，也不会跟随 `common` 符号链接；开机扫描的脚本数从约 170 个降到十余个，同时字域所有 `$MODDIR/common/...` 路径、App 调用、`sh` 执行方式都不变。
- 迁移失败会自动还原为普通目录，安装与开机两条路径都可回滚，不会出现模块因迁移失败无法启动。

## 预期与限制

- 预期 metamodule 挂载阶段减少约 4~5 秒，zygote 启动时刻提前到 6~7 秒附近，PID 有望进入 5000 以内。
- 实际数值需要刷入后完整重启一次，读 `logs/boot-profile.log` 与 `getpid(zygote64)` 核对。
- 本版仅完成本地编译与包完整性检查，未安装、未刷入、未重启手机。
- 符号链接依赖 Root 管理器安装时保留模块内相对链接；若某管理器不支持，开机兜底会退化为普通目录（功能正常，但 NoMount 扫描开销仍在）。
