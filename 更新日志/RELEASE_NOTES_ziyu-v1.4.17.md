# ziyu v1.4.17 — 组合字体集合逐面并行与真实字体容错（本地 Debug 候选）

按用户要求优化手机端「应用字体 / 组合字体」的执行速度，并用用户桌面字体目录中的真实字体做回归测试。回归中发现两类会让同一集合生成整面失败的真实情况，本版一并修正。

## 新增与优化

- **逐面有界并行**：原厂 CJK 集合逐面编译改为按 CPU 数、可用内存和来源文件大小有界并行（复用既有 `font_parallel`，最多 3 个进程）。每个 worker 处理原厂集合中的一个面，进程内跨面复用已解析的来源轮廓与边界缓存，减少重复回放与重复绘制。
- **安全边界不变**：来源变化检查（文件身份 + SHA-256）、逐面原厂布局契约、序列化后契约回读、输出哈希、逐面证明、`TTCollection` 组装后的逐面复查、提交与回滚仍全部由父进程执行；并行只改变计算位置，不改变校验内容。
- **结果确定性**：同一来源、同一原厂集合、同一 fontTools 版本下，串行与逐面并行生成的集合字节一致（桌面端对比输出 SHA-256 相同）。

## 修复（真实字体回归发现）

- **个别字形超出原厂极端水平度量**：部分真实英文字体存在少量超出原厂 `hhea` 极端值（`minLeftSideBearing` 等）的字形。原实现会对整面抛错并中止切换。本版按槽位保留该原厂字形并记录 `retainedUnsafeSlots`，其余字形继续替换。
- **FontTools 无法转换的轮廓**：部分字体包含 on-curve-less 轮廓，`Qu2CuPen(all_cubic=True)` 会抛 `NotImplementedError`。原实现同样会让整面失败。本版把这类单个字形保留原厂并记录 `retainedConversionSlots`，不中止集合生成。
- 两类保留都会写入逐面证明，诊断可核对；不存在「静默忽略」的替换。

## 本地回归（用户字体目录）

- 对用户目录中的 10 个真实中文字体（含 3 个可变字体、不同字重与覆盖范围）与同族 Noto Sans CJK CFF/CID 原厂集合做逐面预检：全部通过映射；其中个别字体存在少量越界字形，修复后可完成完整构建。
- 完整构建回归：普通字体（iOS 苹方粗体）、含 on-curve-less 轮廓的字体（思源黑体 M）、组合来源（幼圆 + 数字新）均逐面生成成功，`protected()` 原厂布局契约前后一致、字形索引与 cmap 不变、专用 Mono 面保留原厂。
- 桌面同条件耗时对比见交付目录 `benchmark.md`（修复前/后、串行/并行；手机端未实测，不作为手机速度承诺）。

## 未验证范围

- 未在手机安装、刷入、重启或做应用显示对照；未测量手机端集合逐面编译耗时与 360 秒切换任务超时的余量。
- 保留原厂的字形（共享字形冲突、越界、无法转换）仍显示原厂字形；如需全部替换需来源与原厂共享关系一致，或后续逐字选择方案。
- 并行收益依赖设备可用内存与 CPU 调度；低内存设备会自动退回更少 worker 或串行，回退逻辑沿用 `font_parallel.worker_budget`。
