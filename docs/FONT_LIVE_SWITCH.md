# 字体热切换

## 当前行为（v1.3.0）

只有本次启动已经验证成功的**字域物理自挂载**可以申请当前启动热切换，允许模式为 Magic Mount、OverlayFS 和字域自挂载。Root 管理器、用户偏好、启动 ID、当前挂载清单与字体契约必须匹配；通用 XML 动态配置等不支持的目标会转为重启应用。程序不会为热切换偷偷改变用户选择。

元模块/管理器内置挂载、恢复系统默认、通用运行时、首次尚未验证的自挂载和挂载模式变更走重启验证。热挂载成功表示 PID 1 文件与路由校验通过；Android 字体缓存仍可能保持旧映射。只有已确认支持的 KernelSU / SukiSU Ultra `ksud soft-reboot` 才能从 App 请求软重启刷新系统界面，且必须由用户确认。

本文后续按历史修复版本记录热切换事务、回滚与性能变化；历史设备记录不代表 v1.3.0 已通过新增机型的真机验收。

## v1.2.46 挂载状态与系统界面缓存

历史只读设备记录确认：当前 SystemUI 路径已是新字体，
进程内 mmap 仍引用约44MB的旧对象，设备号也不同；Zygote / system_server 中同样存在旧映射。
所以重新打开界面或只验证 PID1 路径，不能证明系统界面已刷新。

热挂载后 `font_ui_cache.py` 只读比较实际已验证字体的映射对象与进程当前可见文件，
报告保存在 `config/font-ui-cache.json`。重复文件名存在多个分区候选时不猜测路由；
进程启动身份发生变化的采样不采信；不可读或没有比较证据记为 unknown。
报告只证明观察到的文件映射，不证明全部 Typeface 缓存或实际显示字形已刷新。

`liveApplied` 与 `rebootRequired` 表示挂载任务的明确结果；
`uiCacheRefreshRequired` 单独表示观察到 SystemUI 旧缓存，不把热挂载成功误写为待完整重启。
App 检测到旧缓存后提供用户确认的 KernelSU 软重启刷新；可选择稍后处理。
普通挂载应用、挂载方式变更和模块更新原有的重启要求继续保留。
本版未安装，未执行软重启或视觉验收。

v1.2.40 为已通过当前启动验证的物理自挂载接入运行时更新。用户选择
`magic`、`overlayfs`、`self_mount` 后，必须先重启确认该方式已经生效。
随后 A → B → C 可直接尝试热挂载，不必先恢复默认字体。

## 执行流程

1. 原有连续提交事务先保存下一启动字体负载。
2. 验证当前内核启动 ID、后端、自挂载方式和旧挂载日志。
3. 把下一启动负载复制到新的字体代，不与可写源目录共享 inode。
4. 在 PID 1 命名空间卸载本模块旧目标，保留旧文件和工作目录。
5. 使用独立工作目录和同一挂载方式挂载新字体，校验可见文件和字体路由。
6. 保存当前启动字体指针及验证证据；成功后清除等待重启提示，仍保留下次启动队列。
7. 失败时使用另一个独立工作目录重新挂载旧字体。恢复无法确认时显示失败，保留事务和队列供恢复。

目录、文件及挂载日志不跨代复用，避免覆盖应用已经 mmap 的字体文件。
当前启动使用过的字体代不自动删除；空间不足时保留重启应用队列。
只有内核启动 ID 改变且挂载表没有引用，才清理有本模块记录的旧字体代。
软重启 ID 不变，保留这些文件。

## 状态与限制

“已热挂载”表示 PID 1 文件及路由校验通过。Android Typeface、共享字体映射
和已打开应用仍可能缓存旧字体，不能据此宣称所有界面已经刷新。
用户可以重新打开应用，或主动选择已有软重启功能。模块不自动重启或关闭应用。

元模块、NoMount、通用字体运行时、恢复默认以及首次尚未验证的自挂载，
目前保留重启应用路径。挂载方式在本次启动后改变，也必须重启确认。
不会为获得热切换而自动改用其他后端。

取消晚于热挂载提交时保留已经提交的选择和启动队列，提示已完成；
“恢复上一套字体”会复制热切换前的字体代并准备重启恢复。
重启激活前另存上一套字体代的持久回退快照，避免把仍停留在旧字体的规范目录
误认为热切换前的字体。完整重启后的撤销操作也使用这份实际负载。

## v1.2.41 长路径兼容修复

一份 v1.2.40 实机日志显示：F2FS casefold 下层被内核拒绝后，
启动挂载可使用 ext4 镜像，但热切换和回滚工作目录的镜像绝对路径超过
Toybox losetup 的 64 字节描述字段，创建 loop 设备时报错，导致两次挂载均失败。
改用相对路径也无效，因为 Toybox 会先解析绝对路径。

长路径镜像使用 Root 管理器已有 BusyBox mount；保持镜像文件位置、独立
工作目录、SELinux 校验与用户指定的后端。若旧字体已有 ext4 兼容镜像，
先检查 BusyBox mount 是否可用，缺失时保留旧挂载和重启队列。
目录镜像只读重挂载也优先使用 BusyBox 的明确源、目标参数，并检查只读标志。

App 与脚本导出的诊断日志均包含热切换记录，不再遗漏 App 导出路径。
诊断日志包含 `config/font-live.conf`、`font-live-previous.conf`、
`font-live-transaction.conf`、`font-live-attempt.conf` 和 `logs/font-live.log`。

本次交付只进行静态语法检查、Android 编译和打包完整性检查。
未进行手机挂载、连续切换、异常断电或界面字体刷新实测。

## v1.2.42 重复应用耗时优化

旧版对字体库存 JSON 整文件计算缓存标识，扫描时间 generatedAt 改变就会
使已生成的字体对齐缓存失效。现在对 JSON 内容排序序列化后计算 SHA-256，
只排除顶层扫描时间，保留 ROM、来源、槽位、度量和结构版本等全部其他字段。
JSON 或运行时不可用时，保留整文件标识，不放宽缓存复用条件。

缓存成功复用后更新目录使用时间，淘汰时按最近使用排序；容量上限不变。
旧标识的缓存需重新生成一次，新标识才能避免单纯刷新扫描时间带来的失效。
热切换已存在字体代的内容校验按文件 inode、大小、修改时间及状态时间去重；
各路径仍检查 SELinux 标签并比对预期哈希。没有删除当前启动仍可能被引用的旧文件。

首次处理新字体、ROM 库存内容变化或缓存被容量限制淘汰，仍需要生成字体。
此版本未进行手机耗时测试，不给出实测提速比例。
