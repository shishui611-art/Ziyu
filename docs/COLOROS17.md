# ColorOS 17 适配说明

本 fork 保留字域的原生 App、设备字体清单、复合字体生成、私有负载与自挂载。首次刷入后保持原厂字体；用户在 App 中自行导入并应用字体。工作区中的 iOS26 字体不随本模块打包。

## 补充的目标

旧版 ColorOS 字体加载器 v0.4.9 在用户设备上使用了 `OPSans-En-Regular.ttf`、`OSans-Solid-Digits-VF.ttf`、`RobotoFlex-Regular.ttf` 和系统字体 XML。字域原有逻辑已覆盖常见 OPSans、RobotoFlex 字体及实际存在的字体 XML；本次补上 `OSans-Solid-Digits-VF.ttf`：

- 只在设备上存在该文件时建立同分区覆盖，不生成不存在的目标。
- 将 `osans-solid-digits` 识别为可替换的 UI 数字族，并保留 XML 中的多字重行。
- 将该目标按英文数字字体槽处理；来源字体必须含英文数字，不能用只有中文覆盖范围的文件替换。
- 字体 XML 继续按真实分区扫描；例如 `fonts_base.xml`、`fonts_ule.xml` 只有存在时才处理。

## 与旧模块的区别

旧模块在安装阶段按实际路径生成常见字体文件和 XML 的系统覆盖，主要由 Root 管理器或元模块挂载，部分无元模块场景尝试逐文件 bind。字域在 App 应用字体时先扫描系统字体清单，按中文、英文、数字来源生成并验证负载，再提交私有 `.luoshu-payload`；由字域自己挂载，遇到不完整挂载会尝试回滚。两者的字体文件映射相似，但生成时机、负载组织和挂载责任不同。

本 fork 保持其他 Android 系统的字域扫描方式，不设置机型或 ColorOS 硬性安装限制。ColorOS 17 的具体目标仍须按实际固件检查；SystemUI APK 内置字形或图片不受系统字体文件覆盖控制。

## 版本状态

当前 fork 基于上游已撤回的 `v2.0.0` 源码。上游仓库的 `docs/WITHDRAWN_2.0.0.md` 记录了 HyperOS 英文数字覆盖问题；本次补丁只针对上述 ColorOS 数字槽，不能据此认定上游问题已修复。源码测试和 App 构建也不能替代目标手机的安装、应用、重启及恢复测试。为避免被上游在线更新降到不同版本，本地模块元数据暂不提供 `updateJson`。
