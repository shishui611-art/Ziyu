# v1.4.105 挂载校验与手势修正

## 一处挂载警告

本次连接设备的 v1.4.104 报告 `state=partial`、`appliedCount=14`、`unappliedFonts=[system/fonts/SysSans-Hans-Regular.ttf]`。只读重新执行原校验仍得到相同结果，因而不能简单归咎于旧报告未刷新。

NoMount Suite 1.87 的系统可见视图中，`SysSans-Hans-Regular.ttf` 与 `SysFont-Hans-Regular.ttf` 的内容不同，却返回相同的设备号、inode、长度、时间与模式。分别读取内容时，两者摘要都与各自生成清单一致；旧 `FontDigestCache` 仅按这些身份字段复用摘要，导致后读到的路径使用了前一个文件的摘要。三个 XML 相关警告是这一处文件未验证产生的后续结果，并非另有三个字体挂载失败。

修正方式：

- 系统可见字体使用单独的路径级摘要缓存，跨路径不共享摘要；传统与通用校验路径均覆盖。
- 字域管理的源文件仍使用原身份缓存，保持硬链接去重；每次仍打开路径，检查文件类型与读取前后的身份变化。
- 保留内容与清单对比、可读性、路由、挂载、回滚及部分应用的判断。真正不一致继续失败，没有放宽校验。

## 预测性返回

设置首页原先通过可移动内容在预览容器与动画容器之间迁移，返回完成时会重挂内容。现在首页保持固定位置，详情页覆盖其上；正常转场和预测性手势分别驱动底层位移，手势提交不再搬移首页。

主页面预测性返回不再在回调中强制 `scrollToPage` 同步测量，改为请求下一次布局对齐，并在对齐后解除程序切换标记。目标页及其有限相邻页提前组合，避免提交时才添加目标页的相邻内容；场景数量受固定主页面集合限制。取消返回与历史记录沿用原逻辑。

预热的相邻主页面原本也跟随返回手势移动，可能从侧面覆盖真正的历史目标，提交时才显露目标页，造成视觉跳换。手势期间只显示当前页和历史目标，其他预热页保留状态但不绘制。

主题背景图片按主题作用域共享一次有界解码，不再为当前页、相邻页和返回预览分别解码同一张背景；仍在 IO 线程处理并限制尺寸。作用域退出后可回收，没有全局累积图片缓存；嵌套主题预览使用自身背景，路径变化时不借用旧主题图片。

玻璃底栏仍在固定内容记录层外，不改变采样层位置；本轮不通过关闭玻璃或禁用预测性返回规避问题。

## 纵向滚动误触横滑

仅向外层横向滚动节点提供两倍系统触摸阈值；其内部列表、滑块、分页标签与按钮恢复原系统配置。纵向控件可在原距离取得手势，主页面横滑需要更明确的横向移动。继续使用原 Compose 滚动、惯性、RTL 与翻页吸附流程，不重写逐帧拖动处理，不影响系统边缘返回的触摸阈值。
