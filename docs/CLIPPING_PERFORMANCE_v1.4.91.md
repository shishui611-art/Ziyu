## 处理路径

1. 在既有隔离暂存区内，使用来源身份和内容摘要对批次去重。相同字体字节只测量一次，不跨批次信任可变 Python 对象。
2. 通过原有快照解析器获取并验证所有目标。根据实际全变化范围边界及最紧目标行框，计算同一字体的统一缩放比例；多字面保留来源索引。比例有可能比原先某个宽松目标的单独比例更小。
3. 每个来源字面只生成一次完整缩放模板，保留 fvar/avar/STAT、连续 gvar 变化、字符/UVS 映射及源字形索引。复用原有 FontTools 缩放处理器分块执行，停止对已处理点数据的额外通用遍历；速度优先序列化只更换等值压缩方式，不删点、取默认字重或离散化。
4. 模板仍执行完整变化契约及全字形/全元组边界验证。模板边界必须符合该来源涉及的每个原厂目标；逐个来源字面生成后释放 FontTools 图，模板本批次合计容量上限 384 MiB。
5. 目标输出复用 `FontMetricsIO`，仅改 head/hhea/OS2，其他表复制已验证模板原始字节。逐表比较 SHA-256、表清单、目标行框、模板边界与文件身份；源与原厂快照继续在处理前后核验。TTC 合并后仍检查每面不可变表与行框。不能用默认实例边界代替全可变轮廓证明。
6. 完全可变的批次只需单个头部写入进程；静态字体原并行策略继续保留。低优先级仅作用于本次字体处理进程，不改 CPU 频率、亲和性或系统温控。
7. 既有任务进度文件使用实际阶段、字形与完成文件计数更新，范围 76–85%；发布、挂载验证、回滚、取消及超时仍由原外层事务负责。没有增加重试循环或延长超时。
8. 完整负载成功后仍由既有缓存管理；处理器身份包含并发组件，旧处理器产物不会被当作本版缓存。模板只存于本次模块暂存子目录，失败和结束后清理，不散落到 `/data/adb` 根目录。
