# 字体处理诊断与兼容提醒

## 通用引擎与兼容路径

「通用编译暂未完成」表示至少一个系统字体目标没有生成通用产物，不等同于字体导入失败。
系统会继续尝试兼容切换路径；成功时记录「兼容路径已准备，重启后生效」，只有兼容路径本身
返回非零状态时才记录为实际切换错误。blocked 诊断会列出最多 8 个系统字体目标和各自原因；
其余目标数量会提示到字体切换日志查看。

## 用户提交问题

更新模块和 App 后，复现一次问题，在「字体刷写」右上角点击报告按钮。
将生成的 `内部存储/Ziyu/reports/Ziyu-diagnostic-时间.txt` 文件发给开发者。
截图可以辅助说明，但无法代替报告里的原始异常栈。

报告包含机型、Android/模块版本、Root 与挂载状态、任务参数、字体名称及路径、
错误码、原始异常栈和字体布局信息。只读取指定配置与属性，不采集设备序列号、账号或聊天内容。

## 开发者定位顺序

1. 在 `[config:axes_task.conf]` 中找到 `task`、角色、轴参数与最终状态。
2. 搜索同一个任务编号的 `[MIX_PREPARE]`，确认源文件、当前生成档位和实际取值。
   例如 `generated_weight=100 effective_weight=400 mode=fixed` 表示生成 100 档时，中文输入固定取 400。
3. 查找 `[MIX_PROCESS]` / `[MIX_ERROR]`，查看阶段及退出码。
4. 在 `[persistent-font-diagnostics]` 中读取 JSON 的 `errorCode`、`exceptionType`、
   `source` / `inputs`、`axes`、`traceback`、Python/FontTools 版本与脚本指纹。
5. 若处理成功但有兼容提醒，查看 `variationFallbacks` 的字符、Unicode、所选字重、
   原始字重、回退方式和异常栈，再对照任务结果里的中文提示。

| 错误码 | 含义 |
| --- | --- |
| FONT_SOURCE_NOT_FOUND | 没有找到所选字体族的源文件 |
| FONT_SOURCE_INVALID | 输入字体的基础检查失败 |
| FONT_INSTANCE_MEMORY | 实例化时内存不足，退出码 12 |
| FONT_VARIATION_ASSERTION | 字重处理遇到未恢复的断言异常，退出码 13；需要看原始栈 |
| FONT_INSTANCE_ERROR | 其他实例化异常，退出码 1 |
| FONT_COMPOSITE_MEMORY | 合并时内存不足，退出码 12 |
| FONT_COMPOSITE_ERROR / FONT_COMPOSITE_FAILED | 合并异常；结合 JSON 与子进程退出码定位 |
| FONT_COMPOSITE_INVALID | 生成文件未通过输出检查 |

## 有限恢复的边界

只恢复 glyf/gvar 字体中少量字形的变体增量解码断言错误。
保留该字的原始轮廓，其余字继续按选定轴生成；不修改导入的源字体文件。
任务结果会显示，例如「窒在 400 字重无法处理，已保留原始轮廓」。
该字使用字体默认轮廓，不代表它成功生成了 400 字重。

超过恢复数量上限（最多 8 个，且受字体字形数限制）、原始轮廓不可用、其他类型的异常，
或者复合输出未通过检查时，终止任务，不把它报告为成功。
详细报告独立保存在模块 `logs/font-diagnostics/`，最多保留最近 24 份；导出最近 12 份。

## 本次验证范围

专项回归覆盖：中文/英文/数字恢复、正常字形真实字重、原始轮廓不可用时停止、
多字形损坏时停止、固定/自动组合的可见提醒、失败缓存清理后诊断保留及 App 报告导出。
实际保时捷字体的 400 实例可生成，定位到 U+7A92「窒」，保留其原始轮廓。
APK 编译与包完整性另行检查；手机安装、开机挂载和实际显示仍需用户测试。

这是局部测试包。未执行完整正式发布门禁；Windows 下现有性能测试的超时用例
出现任务先完成而超时断言未触发的情况，不计为此修复的通过证据。
