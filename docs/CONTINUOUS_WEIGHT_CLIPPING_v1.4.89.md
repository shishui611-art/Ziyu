# v1.4.89 防裁切保留连续字重

## 必要约束

用户明确要求防裁切不能失去连续调整字重。v1.4.88 默认字重静态化方案已撤回；本版不调用实例化器生成固定字重替代。此约束也已写入父目录及本副本 AGENTS.md。

## 实际修改

- `prepare_donor` 返回原来源与不可变测量摘要，不修改来源、删除 fvar 或固定轴。ColorOS worker fork 前按来源身份共用摘要；TTC 共用 glyf/loca/gvar/hmtx/vmtx 原始表跨度时共用几何测量。
- 新增 `font_clipping_variable.py`，支持带 wght 的 TrueType/glyf/gvar 来源及其 TTC。遍历全部字形，对每个简单字形按 OpenType IUP 补出临时增量；稀疏存储不被改写。每组 tuple 的影响系数在 0 至 1 之间，逐点累加正/负增量得到覆盖整个连续变化空间的保守控制点包络；XY 组件递归合成矩阵与可变偏移。不是只检查 100、400、900 等少量样本。
- 按可信原厂行框计算统一缩放比例，保持基线与字形比例。调用已随模块提供的 FontTools `ScalerVisitor`，同步处理基本轮廓、gvar 增量、组件偏移和布局/度量 VariationStore，随后恢复来源 UPEM。fvar/avar/STAT 保持原数据。失效的 TrueType hinting 在缩放时移除；原厂行度量和 MVAR 处理沿用原可变字体度量路径。
- 轴映射 avar（含 v2 的归一化坐标 VarStore）在尺寸缩放时排除、随后原样恢复，防止把轴归一化坐标误作设计单位缩放。全局 head 边界按可变轮廓包络补足，不再把原厂默认实例的 bbox 冒充所有可变实例的真实范围；输出时同时核对原厂行框和声明边界。
- ColorOS 在可变结果准备完成后直接接收该已验证输出，避免再走仅处理静态轮廓的原厂字形转写。保留来源 cmap/UVS、字形索引和变量，不把它标成“原厂 cmap/字形索引保持”。静态字体继续原有转写路径。
- TTC 保留来源面索引；目标为原厂集合时要求来源只有一面（填充每个原厂面）或面数量与目标匹配。每面独立核对轴与行框，合并后复核数量、映射、变化拓扑和已验证轮廓/度量表字节，避免丢面或静态化。
- 输出重新打开后核对字形顺序、完整 Unicode/UVS 映射、轴表摘要、gvar 支持域/点数拓扑、有效轮廓变化轴、变化表存在性，并重新计算全范围包络。来源身份与摘要前后核对。失败时不提交，不用默认静态字重掩盖失败。
- 同一批次相同原厂行框复用输出；完整负载仍进入原缓存，新增 helper 已纳入处理器身份及模块清单。关闭防裁切不执行新增轮廓测量。没有增加 App 启动预处理、常驻后台或新的公共目录。
- 测量和验证按字面释放 FontTools 对象，避免在一次 TTC 或 fork 前保留多套可变轮廓图。字形组件深度、展开增量数量、集合面数与输出大小有界限。

## 限制

- CFF2、VARC、彩色/位图、部分 AAT/Graphite 布局及对齐点定位组件暂不支持此路径；混合静态/可变的集合也不转换为固定字重。来源/目标集合索引不兼容时拒绝本次适配。
- 正负增量独立累计是保守包络，可能比真实极值宽；少量异常大字形可能让整套字体缩小较多。本文不宣称任意固定控件、应用自带字体或栅格化像素边界都已解决。
- 首次仍需要读取/处理可变数据。缓存未命中、字体/系统/处理设置改变时会重新生成。没有本版同条件手机耗时证据，不声明已提速或具体耗时。
