## 每次验证顺序

1. **记录环境。** 写明 App/模块版本、ROM 构建号、Android 版本、Root 管理器及版本、所选挂载模式、实际后端、重启方式和本次 boot ID。注明设备及目标应用版本，不能沿用上次启动的通过记录。
2. **检查源字体。** 记录用户字体的 SHA-256、字体集合 face、可变轴值与所选组合方案。逐字符及完整字符序列检查覆盖范围。单个码位在 cmap 中存在不代表复杂文字、组合字符或 Emoji 序列能正确塑形；结合字体回退和实际字形结果判断。源字体未提供的字应记录预期回退来源，不能直接定性为挂载失败。
3. **检查生成负载。** 对比同一语料在源字体和输出字体中的覆盖与塑形；原来具备而输出丢失的字符、变体或序列单列为生成问题。保留输出校验与摘要；不得为让报告通过而移除失败字符或关闭原有校验。
4. **检查路由与挂载。** 核对当前 ROM 的目标槽位、XML family/alias、样式、字重、TTC face 和负载映射。验证本次启动的挂载来源、PID 1/目标进程可见路径和实际字体内容，区分“文件已生成”“挂载存在”“目标进程使用该字体”。只检查目录或文件名不算挂载成功。
5. **检查实际显示。** 在测试可控制的显示位置逐项对比，并核对系统设置、桌面、通知/状态栏及本轮指定应用；美团裁切场景继续作为已有问题的补充验收。需要时检查浏览器/WebView。保留缺字、方框、错字、异常回退、乱码、裁切、基线和行距的屏幕证据。用同一字号、粗细、轴值和布局进行前后对比；复杂序列的比较不得拆散序列。
6. **复核差异。** 显示仍旧时先确认进程字体缓存或应用自带字体；是否需要重新打开应用或完整重启依据既有流程及已有授权执行。不得在普通检测过程中重刷模块、全局卸载挂载或改写系统字体分区。

本基准补充现有设备矩阵和安全回滚验证，不取代它们。出现系统无法启动、严重乱码或持续闪退时，按既有规范记录并停止该配置的推广。

## 差异分类

| 分类 | 判断依据 | 报告方式 |
| --- | --- | --- |
| 源字体缺字/不支持序列 | 原始字体本身无所需映射或塑形能力 | 列出预期回退与实际结果；不直接记为挂载失败 |
| 输出负载丢字 | 源字体可用、生成字体同一字符/序列不可用 | 记录生成前后摘要、face、轴值和差异 |
| 字体路由未覆盖 | 目标 family/样式/槽位未指向预期负载 | 记录具体映射及实际回退来源 |
| 挂载失败 | 应有目标未挂载、来源不符、内容校验失败或运行验证失败 | 记录路径、后端、namespace、boot ID 与失败日志 |
| 进程缓存/应用自带字体 | 系统路由与内容正确，目标进程仍使用旧字体或自身资源 | 记录进程及字体来源；执行允许的刷新后再判定 |
| 显示裁切/度量问题 | 字形正确但轮廓、基线或行框导致显示不完整 | 保留截图、字号、粗细、轴值和适配选项 |
| 待验证 | 语料、字体、设备、目标进程或证据未取得 | 明确未测范围，结果不得计为通过 |

同一项可以同时存在多个问题。字库缺失数、预期回退数、路由未覆盖数和挂载失败数分别报告，不合并成一个含糊的失败总数。控制字符、格式字符、组合附标和变体选择符不按独立可见字形要求机械统计；保留它们所在序列的实际结果。
