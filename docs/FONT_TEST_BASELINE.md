## 2. 验收步骤

1. **记录环境**：App/模块版本、ROM 构建号、Android 版本、Root 管理器与版本、所选/实际挂载模式、重启方式、本次 `boot_id` 及目标应用版本。
2. **核对源字体**：记录源字体 SHA-256、TTC face、可变轴与组合方案，确认哪些字符在源字体中本身缺失。
3. **核对生成负载**：对比同一语料在源字体与输出字体中的覆盖和塑形差异，排查生成阶段丢字。
4. **核对路由与挂载**：确认本次启动的 PID 1 / 目标进程可见路径、XML 映射与文件哈希，确认挂载来源一致。
5. **核对实际显示**：在字域「字库预览」、系统设置、桌面、状态栏及目标应用（含美团等易裁切场景与 WebView）同字号/粗细前后对比，保留截屏证据。
6. **复核缓存**：显示未变时先确认是否属于进程缓存或应用自带字体，必要时重启目标应用或手机复核。

## 3. 差异分类与报告字段

| 分类 | 说明 |
| --- | --- |
| 源字体缺字 | 源字体自身缺少该字符或序列，记录预期回退字体 |
| 生成负载丢字 | 源字体具备但输出负载丢失，附生成前后摘要与轴值 |
| 字体路由未覆盖 | 目标 family / 样式 / 槽位未指向预期负载 |
| 挂载失败 | 路径未挂载、来源不符或校验失败，附 `boot_id` 与日志 |
| 进程缓存 / 自带字体 | 系统已生效，目标进程仍沿用旧缓存或自带字体 |
| 字形裁切 / 度量问题 | 字符存在但存在裁切、基线偏移或行距异常 |
| 待验证 | 尚未实测的项目，保留待测标记 |

每轮验收报告需包含：**基准修订与 SHA-256、测试环境、字体摘要、具体字符与 Unicode 码位、预期与实际来源、差异分类及证据（日志/截图）**。
