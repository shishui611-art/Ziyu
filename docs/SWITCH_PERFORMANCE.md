# 切换性能与升级偏好修复（v1.2.45）

## 当前优化范围（v1.3.0）

当前代码在同一切换任务中复用字体族扫描快照、字重源身份、稳定字体清单指纹、字体表读取与部分 UI/Root 状态读取；安全缓存仅在设备/ROM/输入身份匹配时命中。缓存未命中或首次使用的新字体仍需解析、生成及完整验证。任何优化都不跳过源字体变化检查、输出校验、挂载验证或失败回滚。

这些改动降低重复目录遍历、JSON/表读取和跨进程调用；当前没有 v1.3.0 手机耗时对照数据，不报告具体提速百分比。后面的段落保留 v1.2.45 优化的实现背景与历史测量边界。

## v1.2.45 字重扫描与缓存补全

原安全切换先调用 `find_text_font_file`，ROM 映射再调用 `scan_family_weights`，
之后每个字重都通过 `get_weight_file` 再扫描一次整个字体目录。
现在明确切换先建立本次调用的字体族快照，以上查询复用该快照。
复用原有 `detect_font_family` / `detect_font_weight`，保留扩展名 glob 顺序、
首个文件选择、字重排序和无指定字重时的首个同族文件回退。
安装和字体列表等其他调用没有启用快照时，继续原扫描路径。

旧缓存只包含主源文件身份，遗漏同族 Bold / Medium 等实际字重文件。
缓存键增加快照中每个字重首选文件的路径和身份，并记录 `familyIdentity`；
目录成员变化使快照失效，源变化时停止提交，要求重新发起切换。
保存缓存与最终负载校验前后都检查本次源身份，避免把变化中的来源用于缓存或提交。
日志新增 `[SAFE-SWITCH] family snapshot ... weights=...`。
快照不跨任务持久化；处理器身份也包含字重规则文件，规则修改会使旧对齐缓存失效。
本版首次切换会因缓存身份补全而重新生成，之后才可命中本版缓存。
尚未进行设备速度测量；此优化消除的是重复目录扫描，不省略字体校验和挂载校验。

## 已定位的升级问题

`customize.sh` 在迁移偏好后调用 `luoshu_install_choose_mount_backend(savedPreference)`。
原实现无条件将 `LUOSHU_INSTALL_BACKEND_PREFERENCE` 设为 `auto`，随后写回偏好文件。
此外，`luoshu_mount_preference_get(module)` 忽略传入目录，可能读取安装环境中的其他模块视图。

现在读取明确目录，安装界面保留传入的选择。默认字体和排除标记只影响实际挂载状态，不重置选择。

## 已有耗时证据与优化范围

旧版只读诊断曾观察到同一任务重复生成多个度量结果的耗时开销；这些历史记录用于定位重复表编译，未随当前发布提交，也不能作为 v1.3.0 的性能数据。

原代码虽然删除了已解码的 outline 表，`OS/2.compile` 仍会加载 cmap；
`TTFont.save(reorderTables=False)` 会对已加载表进行编译并再次重排整份字体。
多个原厂度量契约共用一个大字体时，这些工作会重复发生。

新实现继续使用原度量、底部边界与 CJK 路由算法，只改变保存和同次读取的复用方式。
改变的表单独编译，未改变的表从 SFNT reader 直接复制，FontTools SFNTWriter 更新校验和。
缓存以文件身份为键，只存在于本次暂存处理，原始表字节缓存上限 32 MiB；跨次切换仍依赖已有安全缓存。
每个源文件在处理结束后检查是否发生变化，所有结果准备完成后才替换暂存别名。

## 后续读取日志

- `metricsWriteSeconds`：生成一个不同度量结果的耗时，位于字体度量报告。
- `metricsBatchSeconds`：ColorOS 本次度量处理总耗时。
- `rawTableReads` / `rawTableCacheHits`：原始表读取与同次复用次数。
- `cmapCacheHits`：未改变的 cmap 复用次数。
- `directMetricsWrites`：直接保存 SFNT 的次数。
- `[SAFE-SWITCH] cache hit`：复用了已经生成的完整字体对齐缓存。

实际总耗时还包括字体校验、实例化/合成、CJK subset、挂载与回滚；这些必要步骤保持原有规则。
当前 ADB 未连接手机，尚无本版设备耗时数据。
