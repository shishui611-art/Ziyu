## 防裁切

连接手机的 v1.4.87 `fontswitch.log` 记录：2026-11-04 07:14，ColorOS 17，来源 `iOS26PingFangUISC-VF(100-900)默认450`，切换进入 `font-clipping-compatibility`，在 ColorOS 兼容生成阶段因“防裁切需要普通或已选定字重的静态字体”失败。来源为可变字体是本次日志证实的直接原因；不归因于 ROM 更新或挂载失败。

修正 `SlotCompat` 的源准备路径和通用防裁切的集合源准备路径：启用防裁切时，复用 `font_instance.materialize` 的原生实例化/FontTools 回退，在任务私有目录按来源 fvar 默认轴生成静态样本。使用完整 cjk 角色、不做字库子集，保留原文件，核对原来源身份/摘要、静态结果大小、字符与 UVS 映射。样本按不可变来源身份在有限批次复用；换来源时释放字体对象及轮廓缓存。转写器读取样本本身，后续原厂契约、真实输出边界、源变化检查、暂存验证和事务回滚继续执行。

防裁切按固定默认字重适配，可变字重行为不会在本模式完整保留；在设置明确提示。关闭防裁切并重新应用后使用原流程。彩色字体仍不支持；无法解析、实例化、原厂基准或输出验证失败时继续保留原负载，不能跳过检查来显示成功。

## 应用速度与缓存

- 同一 ColorOS 批次在 fork 前按来源身份只生成一次静态样本，工作进程共享只读文件并各自复核摘要；不共享可变字体对象或轮廓缓存。未开启防裁切不执行此准备步骤。
- 通用集合和单槽处理也在有限批次中复用样本，目录随任务清理；不另建常驻服务，不在 App 打开时批量预处理。
- 完整防裁切输出进入现有 `safe-switch-cache`。缓存身份已包含字体与家族来源、系统指纹、原厂清单/快照、处理脚本与防裁切开关；命中后跳过重建，但仍执行源变化、负载输出、挂载与回滚验证。
- 沿用现有最近使用顺序和容量限制（默认最多 3 份、768 MiB 预算，至少保留最近一份）。缓存被清理、来源/系统/设置或生成器变化时重新处理；不能保证所有重复应用均命中。
- `clippingPreparedSources` / `clippingSourcePreparationSeconds` 记录本次准备数量/耗时，现有日志继续记录缓存命中和整体切换时间。本轮没有新版同条件手机耗时数据，不声明已加速或具体速度。
