# 主题字体与槽位覆盖修正（v1.5.46）

本轮完成本地 Debug 编译与包完整性检查，结果随交付目录的 `DELIVERY.json` 保存。未运行功能测试或手机验收；编译与打包不能代替主题还原、字体挂载或软重启实测。

## 主题字体

主题字体功能直接修改厂商在 `/data` 保存的字体，普通模块卸载或撤销挂载不能代替还原。

- 新记录与备份统一放在 `/data/adb/ziyu/theme-store/`，不随模块目录删除。旧版模块内的恢复清单和仍有效的替换签名会迁移到新目录；安装期间仅迁移备份，不改写主题字体。迁移不完整时停止更新并保留旧模块。
- 每次替换都先保存该目标的备份、哈希、权限与恢复记录，再写入同目录临时文件并核验、改名。重复替换保留同一轮原件；还原成功后撤销这一项记录，下一轮重新备份当时的主题字体。进程中断后可从已有记录重试。
- 保留原目标的 uid、gid、权限和可读取的 SELinux 标签。旧版已丢失的原始权限/标签无法凭空重建；旧记录迁移使用现场可读取的元数据。
- 所选字体缺字符、变体序列、对应排版支持，或不能保留原有连续调整范围时，保留该主题原件，不转换或固定可变字重。
- 开关、开机同步、恢复默认、卸载共用同一把主题处理锁。恢复默认和卸载先还原主题字体；未还原项保留记录与备份并返回失败，不报告全部成功。管理器即使忽略卸载失败，独立备份目录仍保留。
- 系统主题服务在替换后又修改了目标时，不用旧备份覆盖用户的新选择，报告冲突并保留两边文件。此类冲突仍需核对日志后处理，不能承诺无条件自动还原。
- UI 读取退出码、状态、失败数量和剩余恢复项。部分失败时仍提供“还原主题字体”，不再无条件显示已更新或已还原。

## 额外槽位

`font_expansion_guard.py` 在单次批处理中读取字符与排版表，复用同一源字体的资料及原厂快照哈希核验；不读取全部轮廓、不逐字缩放、不实例化可变字体。已经在本轮暂存树里的文件不重复进入扩展检查。

新增别名必须有与当前 ROM 绑定、哈希核验通过的原厂快照；所选字体须覆盖对应的原厂 Unicode 字符和 UVS，并具备原槽位使用的排版脚本/语言特性及连续变化轴范围。不能证明时保留原厂槽位。此检查只用于额外扩展，不替代已有核心字体生成、输出核验、挂载验证或事务回滚。

因此覆盖文件数可能少于旧版的 100 个；文件数量不能视为全部文字显示正常。保留原因写入 `logs/slot-coverage.log`，不把原厂保留项标记成已替换。

“保留锁屏时钟字体”由扩展计划与生成后保护共用；关闭后允许通过兼容检查的时钟槽位参与替换，系统要求保护的可变字体/特殊字体仍不强制覆盖。该设置进入切换缓存身份，切换开关后重新应用不复用相反设置的旧缓存。
