# 日文与韩文字体

在字体库导入 TTF、OTF 或 TTC，打开详情可以查看日文、韩文样例。点击应用，完成后按提示完整重启。

## 当前支持范围（v1.5.7）

- 未明确标为日韩的完整中文系统字体沿用原有应用路径。
- 中文覆盖不足、但具有充分日文假名或韩文覆盖的静态字体，自动使用按语言补字路径；不是放行到整份字体覆盖路径。
- 字体内部家族明确标为 JP／KR 等日韩地区、且实际具有对应文字覆盖时，即使也包含完整中文字库，仍走对应语言路径；不只根据文件名判断。
- 日文替换假名，韩文替换谚文、字母及其扩展。没有的字符保留该原厂字体原有字形。
- 仅支持静态字体进入日韩按语言替换路径；日韩专用可变字体、CFF2 与彩色字体不支持此路径，不会通过固定字重或删除变化数据来转换。
- XML 明确只供日文或韩文使用的字体面，可以替换相应共用汉字；中文、无语言标记或多语言共用的字体面保留原厂汉字。因此部分 ROM 上日文汉字仍使用原厂，这是范围限制，不能当作整套日文字形已完成替换。
- 应用一款日韩字体时，其他文字恢复原厂；当前不是同时选择多款中文、日文、韩文字体的组合界面。组合页仍使用原有中文、英文、数字选择。
- Klee 公开说明为 Adobe-Japan1-4 和 GF Latin Core；不是完整韩文或简体中文字库。用户需自行导入字体，模块不附带 Klee。

## 安全与兼容边界

只使用与本次 ROM 对应、哈希已验证的原厂快照。保留字符映射、原厂字形索引、UVS、排版、字体面数量、名称与行距，按语言替换已有字形。没有重写系统字体 XML，也没有覆盖系统分区。代码等宽、斜体、衬线、彩色和图标专用字体面沿用保护策略。

首次处理只读取已捕获的有限字体快照，不扫描分区。复用已有静态轮廓原生桥与有界缓存；源/系统/保留规则变化失效。每次复用仍检查源摘要、输出摘要、逐面原厂契约及缺字回退清单，再进入原有事务和下一启动挂载流程。未进行同条件耗时测量，不宣称具体加速。

日韩专用可变供体、CFF2 与彩色字体暂不进入此路径：应用失败时保留现有字体，不固定字重、不删除变化数据。现有中文可变字体与连续字重路径保持原逻辑。

独立用户规则继续生效。最多 16 个目标文件、128 个原厂字体面、384 MiB 输出；超出限制、没有可信原厂来源、没有安全可替换字符、校验不一致或不支持的格式，均不提交负载。App 自带字体与进程缓存也可能影响显示；需完整重启，不能以预览证明实际挂载。
