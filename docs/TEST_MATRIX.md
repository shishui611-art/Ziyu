# 字域设备验证矩阵

本表记录自动化门禁和已经完成的真机验收，不是 ROM/机型支持白名单。安装时会扫描设备可见的分区、字体目录及 XML 路由；扫描能够运行不等于该机型已经完成字体显示、重启、恢复和卸载实测。

## 当前实现的挂载选择

字域按 App 保存的用户选择执行：

| 用户选择 | 启动选择与实现 |
| --- | --- |
| 元模块自动挂载 | 优先接入当前启动确认可用的元模块/管理器原生提供者；缺失、未知、排除或发布/路由失败时尝试字域自挂载。NoMount 加载后检查实际内核接口，必要时在 service 阶段再核验；不成功仍须回滚并记录结果。 |
| 字域自挂载 | 跳过元模块；尝试 OverlayFS，不符合安全回退条件时使用文件 bind，别名冲突时可使用目录镜像 bind。 |
| Magic Mount | 字域使用文件 bind，别名冲突时可使用目录镜像 bind；不自动改成其他后端。 |
| OverlayFS | 只尝试 OverlayFS；不支持时报告失败原因，不自动改成 bind 或外部提供者。 |

模式变更保存后需重启验证。App 依据本次启动记录分别展示 Root 管理器、提供者、实现方式、PID 1 路由及加载证据；目录存在或模块名匹配不能单独证明挂载成功。自挂载允许部分目标成功并报告 warning；无目标成功、负载损坏或事务无法安全恢复仍属失败。

## 自动化发布检查

正式 Release workflow 会从 `module.prop` 读取版本，运行仓库源码检查、App Lint/单元测试、固定签名检查、APK 与 ZIP 内置 APK 一致性、模块文件清单和发布就绪门禁。只有当检查完成后才创建不可变标签并发布模块 ZIP 与 SHA-256；App 随模块内置，不作为独立正式 Release 附件。

自动化结果不替代真机验收。若维护者明确授权某一版本在矩阵待测时发布，一次性授权文件必须只绑定该版本；readiness 会如实留下待测 warning，不能修改本表伪造通过状态。

## 真机验证进度

截至 v1.4.2，最低要求的四组设备以及 vivo/iQOO 均未完成当前版本的完整实机验收，因此均为**待测**。ColorOS 数字槽策略、按应用只读来源诊断、TTC/OTC 逐面组合生成以及开机/OTA 保护操作，也仍需在对应设备上核实实际显示、启动时序和恢复行为：

2026-10-14 的 OnePlus PJZ110 / Android 17（API 37）诊断记录显示，APatch 115357（a843c526）和 NoMount v2.1.0（500）下，升级后的首次启动及再次应用同一字体后的完整重启成功；APatch 扫描前准备回执为 `prepared`，NoMount 规则包含字体，PID 1 的 14 个字体内容与路由验证通过，后端为 `external`，未回退，最近字体操作错误数为 0。该观察不覆盖更换另一字体、恢复默认、各应用的视觉显示、卸载或其他设备组合，因而不构成矩阵验收通过。

| --- | --- | --- | --- |
| ColorOS 16 / Android 16 | KernelSU 或 SukiSU Ultra | 安装/升级、四种挂载选择、自挂载、字体显示、恢复与卸载 | 待测 |
| HyperOS 3 / Android 16 | KernelSU 或 SukiSU Ultra | 安装/升级、四种挂载选择、自挂载、字体显示、恢复与卸载 | 待测 |

历史只读诊断、CI、APK 构建或 ZIP 检查均不是以上项目的通过证据。添加验收记录时，需提供系统构建号、Root 管理器/版本、选用挂载模式、测试时间、应用/恢复结果及对应诊断或屏幕证据。

## 通用检查要求

- 每次字体字库覆盖、路由、挂载和显示验收使用用户指定的[酷安文章](https://www.coolapk.com/feed/53620096)固定语料，具体来源状态、保存与判定方法见 [字库固定测试基准](FONT_TEST_BASELINE.md)。未取得完整语料或未完成设备对比时，此项保持待验证，不能写成缺失 0 项或已按文章通过。
- 字体清单来自设备扫描，需覆盖实际存在的系统/OEM 分区和字体配置，并记录 family、alias、样式、字重、TTC face 与字体度量。
- 确认安装和覆盖升级后模块偏好保留，禁用/外部排除被尊重；挂载状态与字体路由来自当前 boot ID。
- 至少验证自定义字体应用、各自选后端、部分目标警告/无目标失败、切回另一字体、恢复原厂字体和卸载后的清理。
- 验证字体、fallback、Emoji 与配置目标没有被不必要覆盖；确认失败/回滚有明确结果，日志导出包含相应证据。
- 对热切换，应额外确认仅在受支持、当前启动已验证的字域物理自挂载条件下运行；缓存刷新、软重启和视觉结果单独记录。

任何设备出现无法启动、SystemUI 持续重启、批量闪退或严重乱码，应记录日志并暂停该设备/配置的推广，不把其他机型结果外推为全平台通过。
