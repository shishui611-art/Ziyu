# 字域使用说明

当前工作副本的主模块与 App 版本为字域 v1.4.50 / versionCode 14050。GitHub 当前正式版为 v1.4.2；源码版本号不代表 Release 资产已经发布，请从[最新正式 Release](https://github.com/shishui611-art/Ziyu/releases/latest)核对实际资产。相较 v1.4.2，后续版本增加了系统字号、字重与 DPI 调整、主题预览、字体导出、运行应用字体来源诊断和原厂 TTC/OTC 集合逐面处理等功能，并改进了字体槽兼容与缓存路径。v1.4.50 修复 Material 浅色卡片默认描边缺失、恢复已结束导入历史时重复发送结果通知，以及 SukiSU Ultra 与 NoMount 软重启时旧字域规则残留的问题。原生工具仅覆盖经校验的部分字体路径，不代表全流程都使用原生处理或手机字体切换已提速。设备状态见[真机验证矩阵](TEST_MATRIX.md)。

安装包会同时部署原生库配套模块 `ziyu-font-preload`（管理器中显示为「字域字体预加载（实验性）」），不增加 App。主模块目录为 `/data/adb/modules/ziyu`，配套模块目录为 `/data/adb/modules/ziyu-font-preload`。组件需要已有 Zygisk 实际执行应用回调，并且字域本次启动已验证的字体路径仍对目标进程可见，才会尝试预热 Android 字体缓存；它不能绕过强制排除策略对回调的阻止，也无法处理回调前已经撤掉字体挂载的情形。无 Zygisk 时主模块原有挂载继续工作；可以在 Root 管理器单独停用配套模块，升级会保留停用/移除选择。详情见[预加载说明](FONT_PRELOAD.md)。

安全与维护页面可查看预加载配套组件的启停与本次开机回调记录，也可切换配套组件的启停；完整重启后生效。只有框架实际加载组件并执行回调时才会尝试预加载，组件已安装或已启用不证明框架在运行。

App 还可作为 LSPosed 模块，对用户勾选的目标 App 内系统 WebView 网页文字尝试使用当前系统字体。启用步骤和不适用场景见 [LSPosed 网页字体说明](WEBVIEW_LSP.md)。

## 安装与更新

1. 从[最新正式 Release](https://github.com/shishui611-art/Ziyu/releases/latest)下载页面实际提供的模块 ZIP 和同一 Release 的 `.sha256` 文件，按需核对 SHA-256；源码版本号不代表对应下载资产已经发布。
2. 在 Magisk、KernelSU、SukiSU Ultra 或 APatch 中刷入 ZIP，按模块管理器提示完成重启。
3. 在字域模块的“操作”入口安装或更新 ZIP 内的 App；如果刷写时已自动安装，可直接打开。
4. 首次打开时向 App 授予 Root 权限，并确认字域模块与 App 版本相同。

模块更新包含 App 更新，单独安装 App 不会更新模块功能。Debug 包只有在使用相同正式证书构建时才能覆盖正式版；没有正式签名的本地 Debug 也使用相同包名，但证书不同。历史独立 Debug 包不会自动删除。

## 选择挂载方式

在首页打开“字体挂载方式”，明确选择并确认。新选择会保存；切换后 App 会询问是否立即重启验证。可选择立即重启或稍后重启。模式切换不会在当前启动中热切后端，也不会因失败暗中改成另一模式。

| App 选项 | 实际行为 |
| --- | --- |
| **元模块自动挂载** | 优先交给已确认可用的元模块或管理器内置挂载；提供者缺失、不确定、发布或验证失败时尝试字域自挂载。Root 管理器未识别时，自动回退使用字域 Magic Mount / bind，仍须验证成功。 |
| **字域自挂载** | 跳过元模块；先尝试 OverlayFS，满足安全条件时使用文件 bind 兼容路径；字体别名冲突时可建立保留原厂文件的目录镜像 bind。 |
| **Magic Mount** | 跳过元模块，由字域使用文件 bind；别名冲突时可使用目录镜像 bind。 |
| **OverlayFS** | 只用 OverlayFS。设备内核或文件系统不支持时报告原因，不切换到 bind 或元模块。 |

“挂载详情”显示本次启动记录的 Root 管理器、提供者/元模块及版本、实际实现方式、字体路径验证和错误/警告。`PID 1` 路径挂载观察可能包含其他模块，字域不会仅凭模块名称推断成功。未安装元模块时不需要另装一个来启用其他模式。

刷入时显示自动回退计划，实际挂载在完整重启后的启动阶段执行，不在安装器临时目录中尝试。Magisk/APatch 自带的可用挂载也属于提供者，不要求另装元模块。Root 未识别时的 Magic Mount 使用字域现有 bind 实现，不会假报已检测到 Magisk；没有可用的启动入口、Root 权限或 PID 1 命名空间时仍可能失败。自动回退不改写已保存的 `auto` 偏好，后续启动会重新检测；用户明确选择的模式继续保留。

## 导入和应用字体

可在 App 字体库使用系统文件选择器导入，也可以将字体放入 设置中当前用户目录的 `fonts/`（新默认 `/sdcard/ziyu/fonts/`）。支持的来源包含 TTF、OTF、TTC、可变字体，以及转换后再处理的 WOFF/WOFF2。TTC 作为集合保留，不拆成多个独立文件；重复导入按文件哈希识别。模块 ZIP 导入只提取字体文件，不执行包内第三方脚本；单个 ZIP 最多提取 128 个字体文件、展开总量不超过 512 MB。

1. 在“字体库”导入或扫描字体。
2. 选择中文、英文、数字来源和字重/可变轴。直接字体可将三种角色选为同一字体。
3. 组合字体以中文字体作基底，再将英文和数字目标字形合入。
4. 预览后选择“生成并应用”。
5. 准备完成后重启，再查看挂载结果；不执行热加载。

变量字体的可用轴按文件声明读取名称、范围、默认值与隐藏状态；隐藏轴不展示。若轴读取失败，页面会提示错误，不会据此显示无效的轴选项。

将已保存的组合应用到系统原厂 TTC/OTC 目标集合时，只有能够读取可信 OEM 快照的目标才会逐 face 生成和校验。正常面使用所选组合的静态字重，face 顺序、布局、UVS、样式和度量需通过检查；专用/彩色面、未覆盖字形或依赖关系不安全的槽位保留原厂。遇到共享原厂槽位冲突、来源缺少字形或某个轮廓不能安全转换时，会保留相应原厂字形，并继续处理其余可安全替换内容。该路径不会自动合成所有原厂字重；缺少快照或逐 face 契约不匹配时会保留上一份负载。这里的 OTC 指系统原厂目标集合，不表示 App 用户字体库或 ZIP 导入接受 OTC。

设备扫描以本机可见分区、字体 XML、family/alias、字重、TTC face 和字体度量为输入，不靠固定机型白名单。系统字体未覆盖、应用自带字体、网页 CSS 字体、图片文字和私有字体引擎不保证会被替换。

## 应用状态、警告与失败

- **应用成功**：运行时验证到字体已应用。若同时显示警告，代表有路径或槽位未确认，不应把警告误读为全部系统位置都已替换。
- **部分应用成功**：已有可证明成功的目标，其余目标保留原厂字体并显示路径及原因。
- **应用失败**：没有可证明成功的目标、字体负载/配置不完整，或事务不能安全提交/回滚。
- 设置页可“忽略当前警告”。这会隐藏对应的提醒，不会删除原始日志、改变实际挂载，也不会把未确认路径改为成功。

请在“挂载详情”分别查看后端挂载、文件路由和进程加载/缓存证据。路径尚未确认与挂载失败是不同状态；进程仍映射旧字体也不等于新的挂载操作没有完成。

### 按应用检查字体来源

打开 **设置 → 管理与维护 → 应用字体诊断**。可以从当前运行应用中选择一个检查，也可以扫描有限数量的运行应用。检查只读取应用进程的字体映射和该进程自己的挂载命名空间，不会修改挂载、字体文件或应用设置；单次扫描最多检查 24 个应用，并有明确时间与输出上限。

结果是进程映射来源的线索，不保证当前屏幕每段文字都由列出的字体绘制。应用内置、下载、共享内存或自绘文字可能无法归因，也不会由系统字体挂载自动替换。进程退出、PID 被复用或检查期间字体负载代际变化时，结果可能标为不确定，应重新打开目标应用后再查。

### 开机与系统更新保护

打开 **设置 → 管理与维护 → 开机保护**查看状态。连续两次自定义字体开机未完成后，下一次启动会先暂停自定义字体；系统已完成启动后的 KernelSU late-load 或软重启不按启动失败计数。保护期间建议先在字体库恢复系统默认字体，再完整重启；页面的“解除开机保护”是显式恢复操作，不应通过手动删除标记或状态文件代替。

已建立的系统 build 文件基准变化时，旧字体代际会暂缓加载并请求重新核对原厂字体。按页面提示完成原厂扫描后，在字体库重新应用字体（或恢复默认），再完整重启；只有新启动中对应负载的实际挂载验证通过，OTA 保护才会解除。显示“新字体负载已准备”只代表下次启动负载已生成，不代表当前已加载。若扫描或挂载失败，保护会继续保留；不要反复应用或手工强制启用旧负载。

## 重启应用字体

所有新任务离线准备下一启动负载，保留当前启动字体及回滚条件。KSU/SukiSU 在本机 ksud 支持时可选软重启；其他管理器完整重启。首次模块 ID 升级和用户目录迁移必须完整重启；旧热事务恢复和清理仍保留。

支持 `ksud soft-reboot` 的 KernelSU / SukiSU Ultra 可在 App 确认后请求软重启；此功能不适用于 Magisk 或 APatch。App 的“临时 Root 模式”针对 KernelSU late-load，或由用户在设置中显式启用的 KernelSU 软重启流程；它不会因为检测到任意 Root 管理器就自动开启。若本机 `ksud` 不支持命令，App 会说明无法请求。软重启请求返回成功仅表示请求已接受，重载后的字体挂载还要单独验证。

在 SukiSU Ultra + NoMount 环境中，pre-stop 阶段只标记待清理；`stop` 完成后，字域在 post-fs-data 阶段、NoMount metamount 重铺前检查旧规则。zygote 已停止、PID 1 命名空间正确且字域字体事务锁可用时，程序按虚拟/真实路径和模块分区映射逐条清理字域旧规则；清理失败会恢复原规则并停止后续激活。该流程不清空 NoMount 全局规则，也不接管其 metamount，只覆盖 KernelSU 管理的软重启顺序；任意 root/ADB 命令或第三方后台脚本直接改写 NoMount 规则不受字域锁约束，冲突时流程会阻止激活。v1.4.50 的自动化脚本已覆盖延迟、规则清理和失败回滚，但新 hook 尚未完成手机软重启验收；不要手工删除 NoMount 全局规则。

## 恢复与卸载

恢复系统字体：在 App 选择“恢复系统字体”，等待任务结果，再按提示完整重启或支持的 KernelSU 系列软重启。卸载前建议先恢复默认字体并确认重载验证，然后在 Root 管理器卸载字域。卸载只清除字域记录拥有的挂载和状态；不会删除 设置中当前用户目录的 `fonts/`（新默认 `/sdcard/ziyu/fonts/`） 用户字体。

## 导出诊断与分区报告

App 的“字体刷写 → 日志”页可导出脱敏诊断报告，保存在：

```text
/sdcard/Ziyu/reports/Ziyu-diagnostic-<时间>.txt
```

报告会带上本次挂载状态、分区与字体路由、加载验证、任务错误栈和相关日志。分享前仍应检查设备型号等信息。

需要单独检查设备字体分区时，复制模块中的 `common/font_partition_compat_report.sh` 到手机可写目录并在 Root shell 执行：

```sh
su -c 'sh /sdcard/Download/font_partition_compat_report.sh'
```

脚本只读收集分区、字体 XML 路由、OverlayFS 能力及当前日志，并在脚本同目录生成 `font-partition-compat-<时间>.log`。非 Root 执行会将不可读位置标记出来，报告可能不完整。将此日志和具体失败现象一起交给维护者用于设备适配。

## 常见情况

**只有几个字体路径显示待确认**：先导出 App 诊断报告；不要把待确认直接解释成未挂载。报告可显示每条路径依据、桥接链接或进程映射检查结果。

**OverlayFS 失败**：保留原始失败日志。OverlayFS 是独立选项，明确选择后不会静默换用其他方式。若想让字域在 OverlayFS 安全拒绝后尝试 bind，选择“字域自挂载”；仍须重启验证。

**切换字体耗时**：首次字体或 ROM 契约变化需要生成新负载；符合条件的相同字体组合可复用缓存。该机制意在避免重复工作，不代表已测得特定提速比例。日志页可导出 `[SAFE-SWITCH]` 和字体度量阶段记录。缓存不会跳过源文件、负载或挂载验证。

**字体效果不一致**：确认目标 App 是否使用 Android 系统字体；重新查看挂载详情与部分应用警告。必要时导出诊断报告，不要反复提交同一挂载任务。

## 主页的全局字体与显示

非组合字体显示统一卡片：字体大小使用系统缩放，DPI 读取实际密度；只有已确认的多字重字体且系统支持时显示粗细。组合字体继续在组合页面调节。拖动和“默认数值”只修改草稿，点击“应用调整”后写入并回读；DPI 同时影响界面布局。自带字号、字体或绘制的应用可能不跟随系统设置。

v1.4.11 起，模块安装时尝试读取实际显示参数并保存；未读到时首次打开主页补齐。后续普通读取使用本地配置，返回主页复用已读值。应用调整前仍核对系统当前值，成功后回读确认并更新配置；在其他系统设置页面改动后，点击“同步系统参数”。ROM 指纹或 SDK 变化、配置缺失/损坏、模块自身旧字重迁移后会重新读取；不在每次开机重放这些系统设置。字体轴元数据也按实际文件身份缓存，源发生变化才重新解析。

设置 → 文件与配置位置 → 显示参数配置保存位置，可选共享存储专用目录，例如 `/sdcard/ziyu-config`。配置核对、复制并回读后立即切换，原文件保留；内部小型镜像用于自选目录暂不可用时读取。该选项只影响显示参数配置，字体/组合/备份目录沿用同页的独立选项。挂载、事务及回滚状态保留在模块私有目录。此缓存减少重复查询，不代表已完成同条件启动耗时验收。

挂载默认选自动推荐；手动 OverlayFS、Magic Mount 与自挂载在高级选项中。刷入只准备启动策略，实际生效以重启后的 PID 1 验证为准。

## 用户目录与图片背景

设置 → 用户文件位置：保存共享存储专用目录后，下次完整开机复制并校验成功才启用。原文件保留；冲突或空间不足时继续用原目录，详情可查 user-storage.log。生成的组合字体随字体库迁移，App 私有方案及收藏保留在应用数据；完整备份包含这些设置，由系统文件选择器选位置。

设置 → 外观与主题 → 背景图片：支持 PNG/JPEG/WebP/GIF/BMP 以及系统支持的 HEIF/AVIF；导入后规范为长边最多 2048 像素的静态图片，三个主题可用，完整备份包含图片本身。


## 外观与主题

设置 → 外观与主题中选择 Miuix 或 Material。Miuix 保留原生卡片、按钮与玻璃导航，支持九种取色风格和新版/经典配色；Material 使用 Material 3 Expressive 的动效、色调卡片和圆角。COUI 继续使用自己的主题与原生控件。

v1.4.13 起使用单个手机预览，跟随当前主题与颜色更新。下方可直接选壁纸或固定色，固定色会自动关闭壁纸取色；“更多主题色”提供全部颜色。自动、浅色、深色、纯黑四个按钮同时保存明暗与纯黑选择；切换界面风格或纯黑模式时保留当前页面、滚动和编辑状态。色彩风格/标准点击后单选，选中立即保存。新版规则支持柔和、中性、鲜艳和表现力；其余风格使用经典规则，设置页会说明。配色选择随完整备份保存和恢复。

Material 开启液态玻璃时使用可拖动的透镜指示器；关闭玻璃后为选中项展开文字的实体胶囊底栏。关闭悬浮底栏后使用常规导航。模糊仍可独立关闭；关闭玻璃不会抹掉模糊偏好，重新开启玻璃后恢复。旧 Android/不支持运行时着色器的设备沿用实体回退。图片背景、高刷新率、纯黑模式与所有字体管理功能继续可用。未完成各机型的视觉、交互或资源耗时实测。

## 通知、实时活动与字体任务

首次进入会申请普通通知权限。允许后，如果系统检测到实时活动关闭，会显示一次说明；点击“前往开启”进入系统页面，由用户允许实时活动。选择“稍后”后不反复弹出，可以在“设置 → 通知与实时活动”再次进入。通知及“字体处理进度”类别都应保持开启。

确认应用字体后立即发布“正在应用字体”通知，支持的系统可显示“应用中”或百分比胶囊，点击通知打开任务页。返回桌面时仍更新后台任务进度；结束后转为结果通知。具体胶囊资格、位置及显示由手机系统决定，普通通知授权不能代替独立实时活动授权。导入任务的暂停、恢复和实际完成结果仍会通知；重新打开 App 时恢复已结束的历史记录不会再发送一次旧结果通知。

ColorOS 度量与通用编译会根据可用 CPU、预估内存预算及独立任务数量选择 1–3 个处理进程。它不固定大核/小核，保留前台资源；同一字体来源和契约优先复用。单项计算、串行校验和最后提交不会为了占用多核而重复运行。是否缩短耗时、是否改善桌面交互，需要在同一设备和字体上实测，编译通过不代表性能验收。

## 通知授权与返回手势

设置 → 通知与实时活动中，先确认应用通知已允许，再检查“字体处理进度”类别及分组，最后设置实时活动。返回 App 后自动同步状态；关闭的类别需要在系统中开启，通知级别过低也可能无法显示实时活动。拒绝授权后不会反复自动申请，可主动从此页重试或进入系统设置。

“预览进度通知”会发送独立的 10 秒示例，不覆盖实际字体任务通知，也不执行字体任务。显示位置和实时活动资格以系统实际效果为准，不能用发送成功代替系统已允许的判断。

设置 → 外观与主题 → 预测性返回：Android 14 及以上支持页内跟手预览，取消手势留在原页，完成后才返回；关闭选项或旧系统继续普通返回。设置详情返回设置主页，日志返回原入口，其他主页面返回首页；首页系统返回桌面不拦截。预览层不能触发任何字体操作。手机效果和各厂商手势表现仍待验收。
