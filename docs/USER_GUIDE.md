# 字域使用说明

适用于字域正式版 v1.3.0 及后续兼容版本。模块和 App 使用同一版本；正式版从 GitHub Release 下载的唯一安装包是内置 App 的模块 ZIP。

## 安装与更新

1. 从[字域 Releases](https://github.com/shishui611-art/Ziyu/releases)下载正式模块 ZIP 和对应 `.sha256` 文件，按需核对 SHA-256。
2. 在 Magisk、KernelSU、SukiSU Ultra 或 APatch 中刷入 ZIP，按模块管理器提示完成重启。
3. 在字域模块的“操作”入口安装或更新 ZIP 内的 App；如果刷写时已自动安装，可直接打开。
4. 首次打开时向 App 授予 Root 权限，并确认字域模块与 App 版本相同。

模块更新包含 App 更新，单独安装 App 不会更新模块功能。Debug 包只有在使用相同正式证书构建时才能覆盖正式版；没有正式签名的本地 Debug 使用 `.debug` 后缀包名。历史独立 Debug 包不会自动删除。

## 选择挂载方式

在首页打开“字体挂载方式”，明确选择并确认。新选择会保存；切换后 App 会询问是否立即重启验证。可选择立即重启或稍后重启。模式切换不会在当前启动中热切后端，也不会因失败暗中改成另一模式。

| App 选项 | 实际行为 |
| --- | --- |
| **元模块自动挂载** | 交给本次启动已确认可用的元模块或 Root 管理器内置挂载。提供者缺失、状态不确定、发布失败或路由校验失败时报告失败，不自动改用字域自挂载。 |
| **字域自挂载** | 跳过元模块；先尝试 OverlayFS，满足安全条件时使用文件 bind 兼容路径；字体别名冲突时可建立保留原厂文件的目录镜像 bind。 |
| **Magic Mount** | 跳过元模块，由字域使用文件 bind；别名冲突时可使用目录镜像 bind。 |
| **OverlayFS** | 只用 OverlayFS。设备内核或文件系统不支持时报告原因，不切换到 bind 或元模块。 |

“挂载详情”显示本次启动记录的 Root 管理器、提供者/元模块及版本、实际实现方式、字体路径验证和错误/警告。`PID 1` 路径挂载观察可能包含其他模块，字域不会仅凭模块名称推断成功。未安装元模块时不需要另装一个来启用其他模式。

## 导入和应用字体

可在 App 字体库使用系统文件选择器导入，也可以将字体放入 `/sdcard/LuoShu/fonts/`。支持的来源包含 TTF、OTF、TTC、可变字体，以及转换后再处理的 WOFF/WOFF2。TTC 作为集合保留，不拆成多个独立文件；重复导入按文件哈希识别。模块 ZIP 导入只提取字体文件，不执行包内第三方脚本；单个 ZIP 最多提取 128 个字体文件、展开总量不超过 512 MB。

1. 在“字体库”导入或扫描字体。
2. 选择中文、英文、数字来源和字重/可变轴。直接字体可将三种角色选为同一字体。
3. 组合字体以中文字体作基底，再将英文和数字目标字形合入。
4. 预览后选择“生成并应用”。
5. 按任务结果处理重启提示。看到“已热挂载”时表示当前挂载路径已验证；已打开的系统界面或应用仍可能缓存旧字体。

设备扫描以本机可见分区、字体 XML、family/alias、字重、TTC face 和字体度量为输入，不靠固定机型白名单。系统字体未覆盖、应用自带字体、网页 CSS 字体、图片文字和私有字体引擎不保证会被替换。

## 应用状态、警告与失败

- **应用成功**：运行时验证到字体已应用。若同时显示警告，代表有路径或槽位未确认，不应把警告误读为全部系统位置都已替换。
- **部分应用成功**：已有可证明成功的目标，其余目标保留原厂字体并显示路径及原因。
- **应用失败**：没有可证明成功的目标、字体负载/配置不完整，或事务不能安全提交/回滚。
- 设置页可“忽略当前警告”。这会隐藏对应的提醒，不会删除原始日志、改变实际挂载，也不会把未确认路径改为成功。

请在“挂载详情”分别查看后端挂载、文件路由和进程加载/缓存证据。路径尚未确认与挂载失败是不同状态；进程仍映射旧字体也不等于新的挂载操作没有完成。

## 热切换和重启

本次启动中，**已通过校验的字域物理自挂载**在挂载模式为 Magic Mount、OverlayFS 或字域自挂载时，可直接尝试从一套自定义字体切换到另一套，不必先恢复默认字体。程序会保留旧字体快照；热挂载或回滚验证失败时，保留重启应用队列并报告结果。

元模块/管理器内置挂载、默认字体恢复、通用运行时、XML 动态配置目标、首次尚未验证的自挂载，或当前启动/偏好不符合热切换条件时，任务会要求重启。挂载方式变更本身也要重启验证。热挂载成功只证明 PID 1 文件与字体路由通过验证，不保证已运行进程的缓存即时刷新。

支持 `ksud soft-reboot` 的 KernelSU / SukiSU Ultra 可在 App 确认后请求软重启；此功能不适用于 Magisk 或 APatch。App 的“临时 Root 模式”针对 KernelSU late-load，或由用户在设置中显式启用的 KernelSU 软重启流程；它不会因为检测到任意 Root 管理器就自动开启。若本机 `ksud` 不支持命令，App 会说明无法请求。软重启请求返回成功仅表示请求已接受，重载后的字体挂载还要单独验证。

## 恢复与卸载

恢复系统字体：在 App 选择“恢复系统字体”，等待任务结果，再按提示完整重启或支持的 KernelSU 系列软重启。卸载前建议先恢复默认字体并确认重载验证，然后在 Root 管理器卸载字域。卸载只清除字域记录拥有的挂载和状态；不会删除 `/sdcard/LuoShu/fonts/` 用户字体。

## 导出诊断与分区报告

App 的“字体刷写 → 日志”页可导出脱敏诊断报告，保存在：

```text
/sdcard/Ziyu/reports/Ziyu-diagnostic-<时间>.txt
```

报告会带上本次挂载状态、分区与字体路由、加载验证、任务错误栈和相关日志。分享前仍应检查设备型号等信息。

需要单独检查设备字体分区时，复制模块中的 `common/font_partition_compat_report.sh` 到手机可写目录并在 Root shell 执行：

```sh
su -c 'sh /sdcard/Download/font_partition_compat_report.sh'
```

脚本只读收集分区、字体 XML 路由、OverlayFS 能力及当前日志，并在脚本同目录生成 `font-partition-compat-<时间>.log`。非 Root 执行会将不可读位置标记出来，报告可能不完整。将此日志和具体失败现象一起交给维护者用于设备适配。

## 常见情况

**只有几个字体路径显示待确认**：先导出 App 诊断报告；不要把待确认直接解释成未挂载。报告可显示每条路径依据、桥接链接或进程映射检查结果。

**OverlayFS 失败**：保留原始失败日志。OverlayFS 是独立选项，明确选择后不会静默换用其他方式。若想让字域在 OverlayFS 安全拒绝后尝试 bind，选择“字域自挂载”；仍须重启验证。

**切换字体后任务很慢**：首次字体或 ROM 契约变化需要生成新负载；之后符合条件的相同字体组合可复用缓存。日志页可导出 `[SAFE-SWITCH]` 和字体度量阶段记录。缓存不会跳过源文件、负载或挂载验证。

**字体效果不一致**：确认目标 App 是否使用 Android 系统字体；重新查看挂载详情与部分应用警告。必要时导出诊断报告，不要反复提交同一挂载任务。
