# 洛书 3.0.0 功能移植记录（纳入字域 1.4）

来源为 LuoShu 正式标签 `refactor-v3.0.0`，提交 `3e7e19b9f2b0899a326d0ce337602c006b90f233`。在字域 v1.3.0 源码基础上按功能适配，本次纳入 v1.4.0 正式发布候选。在线更新清单只在实际发布成功后由工作流同步。

## 实现范围

- 两套组合生成器共用新的平顶字形探针、中文比例和基线校正；同一个英数字体使用同一套变换。英数变换都在原始中文基底上计算，避免先替换英文影响后续数字对齐。
- 组合页面新增英数大小（±15%）、上下位置（±10%）和恢复默认。Material、MIUIx、COUI 页面共用控件；App 保存选择，组合方案 JSON 与完整备份包含微调参数。旧方案缺少参数时按零处理。
- 微调参数贯通 Root bridge、生成暂存记录、后台任务、生成清单和 Python 引擎；整数范围在 App、Shell 和 Python 中分别限制。只有配套模块明确报告支持时才能使用非零微调，避免旧模块忽略参数。
- 组合缓存身份包含引擎内容和微调值；校验缓存输出摘要、字体格式以及处理前后源文件和引擎身份。非零微调不能走同源字体直接复制路径；TTC 仍由生成器选择字体面。
- 沿用字域已有实例缓存、并行字体准备和兼容告警。英文与数字保留同一小范围字形集；缓存按实际选中的 TTC 面、字重和轴值区分。同字体、同轴的英数请求顺序复用实例，中文仍可并行准备。缓存命中后继续做各槽位的必要字形检查。
- HyperOS 诊断优先采样设备真实存在的西文路由，记录采集进程内符号链接的目标。导出只包含允许的系统字体路径，其他目标显示为 `other`；该观察不替代 PID 1 挂载或应用缓存验证。

上游日志误报修复已有字域对应实现。任务监督、挂载选择、热切换、失败回滚和字体负载提交继续使用字域现有流程。

## 后续源码优化

- 对齐探针按单次生成、单个字体和具体轴位置保存测量结果。两套生成器在修改中文基底之前共用测量快照，中文探针不再因基线、大小校正和英数两个槽位重复绘制；手动微调复用源字形的高度结果。快照在替换字形前释放，不跨任务缓存。
- 已证明同源、同字体面和同轴的英数请求直接复用变换，不再额外创建仅用于测量数字的 glyph set。
- TTC 首次生成把缓存身份中已经选定的字体面传给实例化过程，省去第二次遍历选择。源文件和引擎变化检查、缓存摘要与输出摘要校验保留；未使用缓存的调用仍自行选面。
- 缓存清理只读取一次文件属性，忽略扫描期间被其他任务删除的条目，不跟随符号链接。
- 英数滑块拖动时在控件内更新数值，结束操作后再保存，减少整个组合页面刷新、偏好写入和方案 JSON 序列化；重复设置相同且已保存的值直接返回。
- 英数微调按当前风格调用组件库的 Slider：Material 3、MIUIx 0.9.3、COUI 1.1.0。MIUIx 配色接入字域当前动态主题，COUI 使用现有 COUITheme。整数步进、禁用状态和结束拖动后保存的行为保持一致。这里的组件库控件不是 Android Framework 的 SeekBar；原有字体轴滑块仍沿用现有实现。

这些优化已纳入后续本地 Debug 编译和包完整性检查；正式版另外执行云端源码检查、App Lint/单元测试及固定签名构建。真机行为和计时仍未完成，不提供实测加速比例。
