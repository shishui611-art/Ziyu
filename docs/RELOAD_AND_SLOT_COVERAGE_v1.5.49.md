# 字体槽位扩展与 KernelSU 软重启

## 槽位发现和替换

设备发现会读取当前 ROM 的字体目录、字体配置和机型清单，结果用于显示和诊断。发布扩展从设备缓存中选择核心拉丁、CJK 和数字槽位，ROM 清单用于补充机型信息，分组标签不会单独限定扩展数量。

其它语种回退、主题装饰、TTC、Emoji/彩色字体和特殊样式字体保留原字体。锁屏时钟按“保留锁屏时钟字体”设置处理，默认保留。CJK 字体按槽位名分类，因此放在通用语言组的繁体中文字体仍可进入检查。

每个拟替换位置都要有当前 ROM 对应的可信原厂字库。所选字体缺少个别字符时，Android 可继续使用字体回退；源字体仍须有有效字符映射。涉及复杂文字的槽位继续核对排版支持，并核对原厂可变轴的完整连续范围。原厂资料缺失、校验失败或替换字体无法保持连续字重时，只保留该位置的原字体。

可变字体直接保留完整变化数据。若原厂字体有可连续调整的字重范围，所选字体必须包含该范围且具有可变轮廓；静态字体不能替代此类位置。

因此扩展数量由设备发现、实际存在的核心字体、用户保留设置、原厂资料和所选字体连续字重能力共同决定。核心槽位范围优先覆盖实际设备，不以 ColorOS 清单的分组交集设定上限；仍按字体角色和原厂数据跳过受保护位置。此前 v1.5.47 的 14 个文件问题来自字体准备时原厂快照不完整。

## KernelSU 软重启

主页只提供普通重启和 KernelSU 内核软重启。KernelSU 软重启会按管理器的阶段顺序重载模块，字域在停机回调中清理自己拥有的挂载/规则，再由正常模块挂载流程发布待应用字体并核对结果。请求被接受不等于字体挂载成功；以重启后的挂载状态、路由检查和日志为准。

## PID 准备

PID 工具只在 KernelSU 已停止 Android 服务、模块挂载完成且系统尚未启动时运行。它在有界次数和时间内调整 PID 分配器的回绕位置，并确认 `pid_max` 已恢复；不会清空已有进程的 PPID，不保证后续进程一定低于某个 PID，也不改变 seccomp。

进入 init 命名空间时只传入内核实际提供的 namespace 参数。若内核未启用 `CONFIG_PID_NS`，系统不会暴露 PID namespace 句柄，此时仍核对 init 挂载命名空间，并且不请求不支持的 `nsenter -p`。只有两个 PID namespace 句柄都存在时，才要求它们一致或进入 init 的 PID namespace；状态不完整时停止 PID 准备。

结果写入 `config/pid-wrap-last.conf`，KernelSU 周期状态写入 `config/temporary-root-soft-reboot.conf`，详细记录位于 `logs/soft-reboot.log`。PID 准备失败与字体挂载结果分别记录。

## 验收范围

槽位扫描、静态字形检查、APK 编译和 ZIP 打包均不能代替手机字体验收。验收时使用固定酷安文章 r1 原文，分别核对源字体、生成负载、系统路由、挂载、进程缓存和字形裁切。当前设备尚未对本次安全槽位策略与无 PID namespace 的 PID 工具修正完成重启实测。
