# 模块已连接，但状态未更新

## 本次证据

用户的 v1.4.96 截图同时显示“模块已连接”和“模块状态未更新”。前者来自轻量握手，后者来自随后的完整状态解析，不能把轻量连接成功视为字体挂载成功。

用户提供的 `Ziyu-diagnostic-20261104-195328.txt` 显示：模块元信息可读、原厂字体清单和扫描记录存在；设备为 OnePlus PLK110、Android 17 / SDK 37，报告识别为 KernelSU。多份字体任务、负载及挂载记录不存在，报告不能据此证明应用了自定义字体，也不能证明字体文件造成连接故障。字体度量中的 missing-glyph 是另一类证据，不等于状态命令失败。

旧报告没有当次 App 状态命令的原始 stdout、stderr 和退出码。尚无法判断该手机是空返回、格式损坏、脚本提前退出还是上下文隔离；不能把 NoMount Suite 或字体本身写成已经确认的原因。

## 执行路径修正

- `common/app_status.sh` 独立读取完整状态；`app_bridge.sh status` 在加载通用字体/挂载引擎前直接委托，旧 JSON 接口继续存在。
- 状态脚本以自身路径确定模块，清除继承的 MODPATH；只加载 Root 身份、当前启动挂载记录、临时 Root、字体运行指针和已有重启标记的窄依赖。保留当前启动标识、实际挂载结果、回滚、下一启动负载、开机保护、真实任务状态的判断，不将握手当成挂载验收。
- 没有任务记录或任务已经结束时不启动两个任务控制器。只有 queued/running 任务仍交给既有控制器核对 PID 等所有权并收敛状态，避免把死任务一直显示为运行中。原有受约束的重启记录收敛继续存在；它可能更新自己的完成记账，因此不将完整状态笼统称为零写入。
- 新 App 直接读取 `app_status.sh kv`；只有模块没有该组件时才使用旧 status JSON 兼容接口，执行失败不自动重跑或切换路径。30 个状态值按固定类型、完整字段、结束标记、版本、模块目录和布尔/数字范围校验。换行、回车和百分号编码后再还原，不执行配置内容，不通过补默认值掩盖损坏。
- 保留 v1.4.96 的随机 Root 回复边界、stdout/stderr 完成码、总超时及取消；本轮不是新建常驻服务。读取失败继续保留上次确认状态，停止附加读取，不修改字体、不切换挂载、不全局卸载。
- App 内存仅保存本进程最近一次握手和一次完整状态回复（每项 stdout 最多 16 Ki 字符、stderr 最多 8 Ki 字符），导出诊断时追加；不自动上传、不额外发起 Root 命令。报告可能包含字体名称、路径及 Root 错误提示，分享前检查。

这是对实际状态加载和传输路径的修改，仍需故障手机回传来确认症状是否消失，不能把新增采集能力本身称为已经修复该设备。

## 给故障用户的 SH

仓库文件：`scripts/ziyu-module-handshake.sh`。同一脚本内置为 `common/module_connection_diagnostic.sh`，已有 v1.4.96 可运行独立文件，无需先升级。

运行前：手机正常开机并解锁，保留发生问题时的 App、模块与 Root 配置，先不要卸载重刷、恢复字体或重启。打开字域，确认报错仍存在，再进入有 Root 权限的终端。

将独立文件放到 `/sdcard/Download/ziyu-module-handshake.sh`，执行：

```sh
su -c 'sh /sdcard/Download/ziyu-module-handshake.sh'
```

Root 文件管理器也可选择“以 Root 执行”。不需要连接电脑。脚本要求 UID 0，不会自动反复申请 Root。

安装 v1.4.97 模块后，也可直接执行内置副本：

```sh
su -c 'sh /data/adb/modules/ziyu/common/module_connection_diagnostic.sh'
```

脚本记录：

1. Root 用户/SELinux 上下文、当前与 PID 1 挂载命名空间、系统版本和必要的模块文件身份；不读取序列号、账号、聊天或全量应用列表。
2. stdout/stderr 通路、轻量握手、当前环境完整状态、清除模块/Python 环境后的完整状态；有新组件时增加键值完整状态。
3. 每条命令的退出码、秒级耗时、输出长度和前 160 字节十六进制，stdout 与 stderr 分节保存到同一个 TXT。旧状态失败或缺少成功标识时至多追加一次限时 shell trace。
4. 固定允许的任务、当前字体、挂载与保护记录；不重新扫描原厂、不处理字体、不刷模块、不挂载/卸载、不重启、不改 Root 隐藏列表、不自动上传。调用旧模块 status 可能触发其已有任务/重启记账收敛。

每条命令独立限时（握手 8 秒、完整状态各 20 秒、trace 12 秒），每路临时输出限制在约 1 MiB。缺少限时工具时停止，不冒险无限等待。报告直接放在脚本旁边；例如将脚本放在 Download 时：

```text
/sdcard/Download/Ziyu-handshake-日期-进程号.txt
```

只需将该 **TXT 文件**发回，里面已包括每步的 stdout/stderr。完成时仅删除此次创建的临时文件；不清理其他文件。若仍有故障，再从同一故障 App 进程导出诊断；终端使用独立 Root 上下文，终端成功不能证明 App 的 Root 授权、隐藏策略和 su 管道也正常。

## 结果怎样判断

- 握手失败：先查看对应 stderr、UID 和模块文件，不能直接判断为字体问题。
- 握手成功、完整状态空返回/非零/超时：根据原始输出和 trace 定位状态脚本；不通过改提示或强制恢复默认绕过。
- 当前环境失败、清理环境成功：检查继承的模块/Python 环境；保留两份原始回复对比。
- 终端两种状态都成功，App 仍失败：对比 App 报告中的同阶段回复，并核对字域的 Root 授权/隐藏策略。脚本不自动更改这些设置。
- 状态正常但字体未变化：继续查实际负载、当前启动挂载、进程缓存或应用自带字体；连接成功不证明显示验收。
